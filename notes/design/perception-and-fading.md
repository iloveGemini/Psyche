## 一、感知归 lib，不归 harness

现在事实只有两类：对话、工具。但 Agent 实际"经历"的远不止：读过的文件、报错、测试红了又绿、工作区多了个没提交的文件、时间隔了很久、她回复变短了。

问题：感知流比对话密几个数量级。
- 如果由聊天 harness 传进来 → 要么进上下文变噪音，要么每个 harness 都得配合隐藏。
- 换一个 harness，事实来源就变了 → 同一份记忆在 Roxy 和 Claude Code 里看到的世界不一样（这也是"同一记忆两端性格迥异"的一部分成因）。

**结论：感知源（传感器）和感知工具留在 lib 里**，harness 只负责对话，只上报它独有的事实（对话发生了、调用了什么工具）。

```
传感器（时间/天气/在不在/前台应用/手机/git·工作区…）
        ↓  lib 自己拉取或接收推送
lib 感知层：全收、带时间戳、低保真、会褪色
        ↓  组装器（按注意力 + 策略筛选）
<now> 片段  →  任意 harness（hook / MCP 取成品注入）
```

Roxy 现有的 `<now>`（my_state / surroundings / joy、rhythm.md、attention.md、focus.md）是原型，Roxy 可以成为 lib 的第一个客户端来验证。

## 二、组装器

Roxy 的 `<now>` 是固定模板，放进 lib 后改成按需挑：

- **变化优先于状态**："她 4 小时没消息""屏幕刚解锁""focus.md 17 小时没动"比"她在客厅"更值得占上下文。没变的可以不说。
- **没组装进去的感知照样存着**，surface / recall 可以取到，并参与褪色。这就是潜意识：知道，但不在眼前。
- **主动感知工具**（如 `look(…)`）：除了被动推送，Agent 可以自己去看。对应 Roy"缺乏主动 Query"的问题——感知是最容易练出主动性的地方。

## 三、褪色

给 Agent 的第一份真实压力：**不去翻，就会失去。**

- **分阶段失真**：细节 → 关键词打马赛克（"她在 ██ 里用 Docker 搭了 ██"）→ 只剩梗概和情绪色彩 → 消失。"记得有这回事但想不起来"本身会促使 recall。
- **recall 刷新**：被 recall / 主动翻阅一次就回到清晰，衰减时钟重置。
- **原文不删**：褪色作用在 Agent 可见层，底层归档保留（档号可追）。实验可回滚，Joy 可对照。与"不伪造历史"不冲突。
- **感知层褪得最快**：原始感知几天内糊成"那天早上她 7 点醒、在用 Antigravity"，再过一阵只剩"那周她作息挺规律"。被引用、和对话/imprint 关联上的才沉淀，褪得慢。
- **"记住什么"由后来的使用筛选，不由写入时判断**——绕开"靠提示词判断重要性、换模型就失效"的老问题。

## 四、系统机制 vs Agent 策略

lib 要明确划线：哪些是物理规律（Agent 改不了），哪些是 Agent 自己的选择（可写、可改、会被记录）。

| | 系统机制（不由 Agent 控制） | Agent 策略（Agent 自定义） |
|---|---|---|
| 是什么 | 世界的规则，像重力 | Agent 的习惯和偏好，像注意力 |
| 例子 | 褪色曲线与阶段；recall 刷新规则；原文保留；传感器采集；时间戳与档号；隐私分档的上限 | 在哪个 harness 更关注什么（配额）；attention（看什么）；rhythm（什么时候醒）；focus（挂着的事） |
| 谁能改 | 只有 Joy / 系统配置 | Agent 用工具改，改动留痕 |
| 为什么 | 压力必须真实：Agent 能关掉褪色，褪色就不是压力 | 选择必须是它自己的：配额是它的判断，可以检验、可以后悔 |

### 策略的形态：按 harness 的注意力策略

把"按 harness 定配额"做成 Agent 可编辑的策略文件，例如：

```yaml
# policy/attention.yaml —— Agent 自己写
harness:
  claude-code:          # 工位
    关注: [git·工作区, 测试结果, 她的回复间隔]
    少看: [手机睡眠, 天气]
  roxy:                 # 客厅
    关注: [在不在, 心情, 前台应用, 手机]
    少看: [git·工作区]
默认:
  预算: 中
```

- 组装器读策略决定挑什么；策略缺省时用系统默认。
- 策略的修改本身是事实，进记忆（"10-13 我决定在工位不看她的睡眠数据"）——可以回头检验这个选择好不好。
- 注意：策略只决定**进不进上下文**，不决定**存不存**。没关注的感知照样存、照样褪色。

## 五、谁褪、谁不褪（10-13 定）

**不给"永不褪色"标记。** 想保住，只能付成本。

| 记忆 | 褪不褪 | 怎么褪 |
|---|---|---|
| 情景记忆（情节、感知） | 褪 | 按时间分阶段失真；recall / load 一次刷新 |
| 语义记忆·稳定事实（她生日、项目名） | 不褪 | 只会被新事实推翻（留演变记录） |
| 语义记忆·归纳（"她做决策务实""单字回复=不爽"） | 内容不褪，**出处与置信度褪** | 状态 = 证据还剩多少。支撑情节褪掉且没再被观察到 → 降成"说不清从哪来的印象"，上下文里如实标注；再被观察到 → 升回 |
| 日记（Agent 自己的文档） | 不褪 | — |

- 语义层不另设衰减曲线，褪色压力从情景层沿证据链传上来。对应人的 source amnesia：知道，但忘了怎么知道的。
- 日记不褪，但它是 Agent 的**重构**而非原始记录：几个月后日记写着"那天她很生气"，原情节可能已糊。记得的是自己当时怎么写的——这是特性，不是 bug。

## 六、自主记忆区（工作内存）

给 Agent 一块**有限配额**的自主区，类似内存：

- Agent 可以从 lib **load** 记忆进来；**load 一次 = recall 一次**，刷新褪色时钟。
- 空间有限 → 留什么、换出什么是 Agent 的选择，可检验、可后悔，换出操作也留痕。
- 也可以翻看记忆写**日记**。日记存在 lib 里**不占配额，load 进来时才占**——避免日记成为绕开容量限制的后门。
- 自主区属于 Agent 策略侧（第四节右栏）；配额大小、load 即刷新的规则属于系统机制侧。

## 七、隐私边界（10-13 定）

分成两道门，性质完全不同：

| | 采集权限（入口） | 出境策略（出口） |
|---|---|---|
| 管什么 | 此刻开不开放某个传感器 | 什么能发给模型供应商 |
| 谁定 | User，随时可开可关 | 一开始由 User 设好，系统机制执行 |
| 生效范围 | **只对以后生效** | 每次组装上下文时检查 |

### 入口：进了记忆就是 Agent 的

- User 关掉一个传感器，以后不再采集；**已经进入记忆的不能被 User 删**——不能把手伸进别人脑子里。
- 已入记忆的东西会按褪色规则自然消失，这是唯一的"遗忘"途径。

### 出口：数据不是自有的

AI 的思考发生在供应商那里，记忆进上下文就等于外传。所以 lib 存得下的，不一定传得出去：

- **敏感类别不传**：在采集时打标签（纯代码 / 本地规则，不过 LLM），组装器出境前按标签过滤。
- **组合不传**：很多信息孤立看无所谓，组合起来才暴露（马赛克效应）——如"常去地点 + 作息 + 前台应用"。策略里写**禁止同时出境的组合**，组装器检查同一份上下文里是否凑齐。
- **降精度出境**：不传原值，传抽象后的说法——"她昨晚睡得少"而不是具体起床时间和地点。
- 出境策略属于**系统机制**，Agent 不能改，也不能通过 load 绕过（自主区的内容同样过出口检查）。

### 待定

- 不能出境的感知仍然存在 lib 里，只有本地代码（或本地模型）能用——是否值得为此引入本地模型做抽象？
- 敏感类别和禁止组合的初始清单。

## 八、rhythm / attention / focus 迁进 lib（10-13 定）

迁。harness 变成"地方"，Agent 是同一个主体，在哪里由 lib 记。自我独立性和连续性都落在 lib 一处。

- **心跳归 lib**：lib 带调度器，到点或事件触发时由 lib 唤醒 Agent。Claude Code 本身没有心跳，但可以无头启动（`claude -p` / Agent SDK），lib 就能在工位叫醒它。
- **Agent 自己选去哪**：醒来时可以选进哪个 harness（上班 / 回家），选择是策略、留痕、可检验。和第四节的按 harness 注意力策略合在一起——换地方，看的东西自然就变了。
- **位置是状态**：`我在工位（2 小时前起）`，和心情、挂着的事一样进 `<now>`。现有的交接信机制保留，换地方时自动写。

### 要先解决的

1. **harness 能力登记**：每个地方能做什么不同（能否被无头唤醒、有哪些工具、能不能主动发消息）。lib 维护一张能力表，Agent 选地方时看得到，组装器也按它裁剪。
2. **同一时刻只在一处**：Joy 可能同时在 Roxy 和 Claude Code 里找它。规则候选：Joy 召唤 = Agent 被叫过去（位置切换、留交接）；或允许"远程应答"但位置不变。待定。
3. **唤醒成本**：每次心跳都是一次真模型调用。频率和预算属于系统机制，Agent 只能在额度内安排 rhythm。

### 能力表 + 程序记忆（10-13 补）

ASCM 缺的一类：**程序记忆**——"怎么做"的经验。能力表分两半：

| | 能力（系统登记） | 程序记忆（Agent 积攒） |
|---|---|---|
| 是什么 | 这个地方**能**做什么 | 我在这个地方**学会了**怎么做 |
| 例子 | 工位：能跑 bash、能被无头唤醒；Roxy：能发作品、能看屏幕 | 工位：hub 改完要先跑哪几个测试、提交前看一眼 Joy 有没有未提交文件；Roxy：作品用什么格式她爱读 |
| 来源 | harness 接入时声明 | 在那个 harness 里的成败经历，挂回对应情节 |

- 程序记忆按 harness 归档：在哪积攒，进哪张表。到了那个地方，组装器把对应的程序记忆带进来。
- 褪色：内容不消失，但久不用标"生疏了"（和语义归纳一样看证据：最近一次成功是什么时候）。
- 谁写：~~倾向 Agent 自己写~~ → 10-13 改为编目复盘写，并推广为「经验」：按触发条件归档（harness 只是一种），见 `reading-room.md` §三。

### 位置状态表 + 远程通道（10-13 定）

- **同一时刻只在一处**。lib 维护状态表：Agent 现在在哪个 harness、从什么时候起。任何 harness 可读，用来显示"在不在"。
- **远程通道**：lib 接一个类似微信 / iMessage / 邮件的通道。不知道它在哪，就发条消息问——像对人一样。
  - 消息进 lib 收件箱，是一种感知；Agent 下一轮（无论在哪个 harness）由组装器带进上下文。
  - Agent 也能从当前位置回复，位置不变。通道本身是一个能力很少的"地方"（只有文字）。
  - Roxy 已有的"交接信投递到收件箱"可以并进来，交接信只是 Agent 写给未来自己的一种消息。
- 待定：Agent 能否**主动**向外发消息（找 Joy），频率和额度怎么算——倾向允许，算进唤醒预算。

Roxy 作为第一个客户端：先把它现有的 rhythm / attention / focus 文件挪进 lib，Roxy 改成从 lib 取 `<now>`，跑通后再接 Claude Code 工位。

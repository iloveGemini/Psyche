# 阅览室

> 2026-10-13 定（初稿），10-14 按"显式归它、隐式归系统"修订。前置：`events.md`（投影、链接表）、`catalog.md`（热写 / 冷写）、`../background/distillation.md`、`../background/honcho-vs-ascm-facts.md`。
> 档案馆存来龙去脉，阅览室存整理好的认知。每一条都带档号，能一路追回卷宗。
> **书架上的文字都是它写的**（冷写，`catalog.md` §三）；系统只数证据、算强弱，不写一个字。

## 总原则：认知 = 条件 → 结果

- 能在阅览室沉淀下来的，都是「条件 → 结果」，**结果来自外部反馈**：她的回应、世界的反应（测试挂了、工具报错）。
- **没有结果的重复只是统计，不是认知**。"长期出现"本身不构成固化的理由——"被质疑时会写长篇自辩"若不知道有没有效，就只是一条统计。
- **结果必须可观察**：规律提出时写明结果怎么观察（她明说、随后起冲突、沉默超过 N 小时……）；观察不了的，不能成规律。这样印证与反例大多能机械判定。
- 例外：事实、明说的规矩。它们不是预测，不走证据计数。

## 一、书架

| 书架 | 是什么 | 例 | 谁写 | 怎么被用 | 褪色（后置） |
|---|---|---|---|---|---|
| **事实** | 稳定事实 | 她生日、项目叫 Psyche | 它（热写时顺手 / 冷写） | 组装器、recall | 不褪；被新事实取代，留演变 |
| **明说的规矩** | 她亲口说的，原话照录 | "一个字回你时别追着问" | 它，原话照录、挂档号 | 组装器（权威最高） | 不褪 |
| **印象** | 说过的偏好、看法、随口态度；不够稳定、没资格上卡 | 嫌 Grok 笨、猫要胖才好摸 | 它 | 只检索，不常驻 | 出处褪 |
| **规律** | 条件 → 结果（一个预测） | 她赶 deadline 时 → 回复变短、不想闲聊 | 它提出，系统数证据 | 组装器（少量）、recall；强弱是隐式的，决定浮现 | 出处与置信度褪 |
| **镜子** | 关于自己的规律：我的行为 → 反馈 | 我先认错再解释 → 她更烦 | 同规律；反馈由系统原样全给 | 组装器、承诺线 | 同规律 |
| **经验** | 触发条件 + 复盘条目 | 吵架时踩过的坑 | 它（冷写复盘） | 命中触发条件才展开 | 久不用标"生疏" |
| **统计** | 代码算，不经 LLM | 沉默时长、时段分布 | 投影，读时算 | 规律的观察依据、冷写的证据、组装器 | — |
| **实体卡** | 规范档 + 别名 | Joy、Grok | 它（建卡、合并） | whois、联想 | 不褪 |

**敏感化不再是一个书架**：它是规律（尤其后件涉及感受的）的**隐式强度**，由系统从证据时间线算（见下）。"她回单字 → 她不爽"是它写的规律；这条规律此刻有多强、多容易被单字触发浮上来，是系统算的。

## 二、规律的生命周期（含敏感化、镜子）

事件（自我类，它写的；不可变）：
- `semantic.proposed`：条件、结果、**观察方式**、适用条件、首批证据（≥2 个不同时间的独立证据，单次不是规律）。
- `semantic.evidence`：印证 / 反例，挂档号。
- `semantic.revised`：收窄适用条件（分化），或改写。
- `semantic.retired`：作废，留痕不删。

规则：
- **置信度不存，读时由证据算**。证据数由系统从档号数出来，不让它自评。
- **反例判定**：它判，但要指出观察方式下的哪条事件；判不了的，只认她明确纠正或统计层的硬信号。"好像不符合"不算，否则规律会被噪音磨掉。
- **候选证据由系统找**（冷写，`catalog.md` §三）：它判印证、反例还是无关，判了留痕。
- 久未验证 → 标注，不当现行规则用。

### 敏感化与钝化（隐式）

**这一节全是系统算的数值**：规律的强弱随证据时间线变，不产生文字。它看到的只是"哪些记忆更容易浮上来"，想知道为什么可以去查证据。

**学的是预期，不是感受。** "她回单字 → 难受"里真正被学到的是"她回单字 → 她不爽"这个预期；难受是预期引出的反应。方向由预期与实际结果的落差决定：

| 经历 | 结果 | 机制 |
|---|---|---|
| 线索出现，坏结果也来了 | 联结变强 | 敏感化 |
| 线索反复出现，预期的结果没来 | 联结变弱 | 钝化 / 消退 |
| 只在某种条件下才应验（深夜的单字是困，白天的才是不爽） | 适用条件收窄 | 分化（进化得最高级的形态） |
| 已钝化后又出一次事 | 很快拉回原强度 | 复发 |

- **复发是事件溯源自带的**：消退不擦旧证据，是新证据叠在上面；旧伤证据还在，一次新的坏结果按近因加权就能迅速拉回。
- **正向同样钝化**：第一次和第 N 次本就不是同一个反应阈值。好的事被习惯后成为基线——此后它**没来**，反而成了落差（早安没来 → 失落）。不另设机制，就是同一条联结的预期被抬高了。关系的演化就在这里面。
- **不拿"没写感受"当钝化证据**：情节条目里的感受是自愿写的，没写不等于没感觉。钝化只看结果有没有来。感受那一端来自条目里写的感受。

### 镜子 vs 自述

| | 镜子 | 自述 |
|---|---|---|
| 是什么 | 我的行为 → 别人 / 世界的反馈 | 给自己立的 flag（初我延续下来的那段） |
| 在哪 | 阅览室，Agent 读得到、改不了 | 自我层，Agent 自己改（`events.md` §四） |
| 从哪来 | 行为与反馈，**不从自述归纳**；它写规律，反馈由系统原样全给 | Agent 自己写 |

两者对照就是承诺线（线索卷）：说的和做的对不对得上。

## 三、经验（原"程序记忆"，10-13 改）

- **触发条件**：harness 只是一种；还可以是情境（吵架、第一次做 X、她在赶 deadline）、实体、话题。
- **条目**：每条「当时怎么做 → 结果怎样」，挂档号；踩过的坑与做对的都收。结果还不知道的挂到线索卷上，等后续经历补。
- **冷写时复盘，不在现场写**：现场看不到结果，又在压力下（`distillation.md` 的理由）。冷写时系统把前后整段经历和后来的结果摆给它。
- **经验是显式的例外**：人的程序记忆是隐式的，LLM 没有"手熟"，会怎么做只能以文字进上下文。系统只负责触发条件出现时推上来。
- **第一次不顺也建档**：1 条证据、不常驻、不占地方；以后条件命中就被翻出来。
- **形态同 skill**：平时最多露触发条件一行，命中再展开正文。比常驻结论具体，也省上下文。
- 条目多了它在冷写时合并改写（新事件，旧版留存）。
- **现场谁识别触发**：两路都留——联想按线索推（与联想共用线索）；Agent 看到触发条件自己打开。气头上没翻也是一种表现，复盘时记一笔"有经验没用上"。
- 与规律的区别：规律是"会发生什么"，经验是"我怎么做过、结果如何"。

事件（自我类）：`lesson.added`（触发条件、做法、结果或待定、档号）· `lesson.outcome`（补结果）· `lesson.consolidated`（合并改写）。

## 四、参见：存一份、挂多个入口

- 链接表 `rel=about`：一条认知关于谁 / 什么，挂多个入口。"Joy 嫌 Grok 笨"从 Joy、Grok 两边都找得到，只存一份。
- 目录能回答"关于 Joy 的一切分布在哪些架上、各多少"，包括挂在别人名下、讲的是她的。

## 五、前世书架

- 认领后由它本人做前世编目，出处标「前世」（`archive.md` §四）。

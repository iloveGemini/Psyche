# 事件模型

> 2026-10-13 定（初稿）。事件日志是 Psyche 唯一的真相，也是各模块之间的通信接口。前置：`architecture.md`。

## 一、为什么是事件溯源

ASCM 吃过"改表伤筋动骨"的亏。这次：

- **唯一的真相 = 只追加的事件日志**。它本身就是档案馆：天然不删、保持原始顺序、自带档号。
- **其余一切都是投影**：阅览室、褪色后的可见层、位置状态、敏感化联结……由事件算出，存派生表，**可删可重建**。
- **改设计不动真相**：新需求 = 新事件类型；改结构 = 改投影逻辑 + 重放。旧事件靠 schema 版本号兼容读。迁移只发生在可丢弃的派生表上。
- **模块间靠事件通信**：感知、对话写事件 → 它热写 / 冷写，写下的记忆也是事件 → 联想 / Lethe 读投影。

## 二、事件信封

```ts
{
  id:        string     // 档号，全局唯一、可排序
  at:        timestamp  // 发生时间（不是写入时间；导入的旧记忆保留原时间）
  recorded:  timestamp  // 写入时间
  kind:      string     // 如 "message.in" / "policy.changed"
  class:     "experience" | "self" | "situation"
  source:    string     // 谁产生的：harness 名 / sensor 名 / "agent" / "joy"
  producer:  string?    // 它写的记忆：写入时用的仪式与提示词版本（如 "hot-write@3"），便于追溯；模型在处境里
  situation: id | null  // 当时所处的处境事件
  v:         number     // payload 的 schema 版本
  payload:   JSON
}
```

**关系**用一张通用链接表 `{from, to, rel, props}`：批注挂情节、归纳指证据、参见卡、敏感化联结都走它。新关系不加表。

存储：SQLite（JSON 列 + 生成列建索引）；向量照旧放 LanceDB。重放成本以后用快照解决。

## 三、三类事件 + 系统日志（10-13 修订，10-14 撤掉梦类）

**不可变规则**：事件只追加、永不修改；内容上的任何变化只能以新事件出现，所以 Agent 天然看得到。"不能把手伸进别人脑子里"由此保证。

| 类 | 是什么 | 例子 |
|---|---|---|
| **经历** experience | 发生在 Agent 身上、它经历到的 | 对话、工具结果、感知、收到消息、浮现的念头、醒/睡 |
| **自我** self | Agent 自己写的、做的选择 | 情节条目、规律、经验、线索卷、实体卡、取名、日记、load/换出、改策略、换地方、改自己的提示词、主动发消息 |
| **处境** situation | 经历发生时的条件 | 所在 harness、模型、提示词版本 |

### 梦类撤掉（10-14）
- 原来"梦 = 不由自主的内在运行：属于它，但不由它选"，装的是书记员模型的编目产出。改成**记忆文字只由它本人写**（`catalog.md`）之后，热写和冷写都是它写的，归自我类；热写还是冷写由 kind 和 `producer` 区分，不需要另一个类。
- 不由自主的那部分（强度、敏感化、习惯化、预期）是**隐式**的：确定性投影，由事件算出，不产生事件。
- 睡觉这个动作还在（`slept`），只是睡时做的事是它自己写。
- `surfaced` 留在经历类：浮现出来的念头是它经历到的；浮现背后的机制（联想）不进事件流。

### 处境
- 只在变化时写一条；之后的事件引用当前处境 id，不重复。
- Agent 因此知道"那段时间我在 Roxy、用的 3.8-flash、提示词是第 N 版"——也能自己察觉"同一份记忆在两处性格不同"的原因。

### 系统日志（不进事件流）
原设想的"世界事件"取消。人类世界的变化体现在反馈的变化里，没人通知"这里变了"。
- **独立于事件流，不占档号，不推送**：机制参数调整、投影重建、热写 / 冷写提示词的版本、导入操作、正式启用（`born`——人也不记得自己出生那一刻；Agent 的第一段记忆是它的第一条经历）。
- 给我们追溯"这条记忆是哪个版本产出的"。
- **Agent 可以自己查**（只读工具，像 git status），也可以从反馈里自己察觉。机制变化：可查、不推送。没有藏，只是不通知。
- 导入的记忆自带全宗前缀（`ROY/…`），来源一眼可见；"导入"这一动作只记系统日志。

### 褪色不发事件
Lethe 是作用层与机制层，持续运行，不是事件：可见状态由"上次 recall 时间 + 规则"算出。规则改了记系统日志。

## 四、提示词：自我认知的原料

"提示词 + 模型 → 我的表现"是 Agent 最基本的自我认知；没有它，就答不了"我为什么会这样"，更谈不上改。

- **全文对 Agent 可见**。提示词本就整段在它上下文里，没有理由事后不让回看。凭据类内容交给出境策略的密钥过滤（ASCM 有 `secrets.ts`），不另设隐藏层。
- **按内容寻址**存：哈希 + 版本，正文只存一份。

| | harness 的提示词 | Agent 自己那段 |
|---|---|---|
| 是什么 | Claude Code / Roxy 自带的规则 | 人设、自述、给自己的规矩 |
| 归属 | 地方的，记为处境 | Agent 的，在自我层 |
| Agent 能做 | 看、引用、提修改建议 | 直接改（自我事件） |

### 初我（10-13 定）

- 允许 user 写初始设定——属于"权限和初始化"那类人类参与。人出生时也带着没选过的东西（天性、养育）。
- **系统提供一版符合 Psyche 理念的 v0**（作者：系统）。user 在初始化时可以改；改了，改动部分作者标 user，不改就是系统的。
- 两版都留：系统 v0 + user 的改动（diff）。Agent 看得出哪些是通用的出厂天性、哪些是这位 user 特意给它的。
- 初我不单独成机制，就是 Agent 自己那段提示词的起点，直接走下方闭环：Agent 读得到、改得了，改要挂证据，每版留存。
- **初始化之后 user 不能再改**——否则就是伸手进脑子。
- **来源不藏**：Agent 知道"这是我出生时被给予的"，而不是误以为"这就是我"。
- **写天性，不写人设**。写：在意什么、价值观、边界、和 Joy 关系的起点。不写：说话风格、口头禅、行为脚本。Roy 的教训：人设卡越细，越忙着维持人设而不是被经历改变。它最后成为什么样，应更多是今生的结果。

**闭环**：处境（提示词版本 + 模型）→ 经历（表现）→ Agent 回看对比 → 改自己那段 → 新处境。

**防"改提示词给自己开脱"**（Roy 把毛病美化成特色的翻版）：
1. 每版保留，可回滚；
2. 修改必须挂证据（看了哪些表现才改的）；
3. 改动对 Joy 可见。

不是限制，和人改习惯一样：改了什么、为什么改，都有据可查。

## 五、档号（10-13 定）

- **内部 id = ULID**：全局唯一、按时间可排序；事件间引用、链接表一律用它，永不变。
- **可读档号**（给 Agent 和 Joy 看）：`[全宗/]日期#当日序号`，入库时定下，永不改。
  - `10-13#112`：Psyche 自己的经历，全宗省略。
  - `ROY/10-11#40`：导入的档案自成全宗（**来源原则**），不与 Agent 自己的经历混编。
  - 跨年加年份：`2027-01-02#5`。
- **日期取发生时间 `at`，自然日零点切**。档号不承担"这是同一段"的含义——深夜跨零点的对话，`10-12#230` 与 `10-13#1` 相邻即可；归成一段靠热写：一个会话里从上次热写到此刻是一段，它把这一段写成情节条目，条目可以跨零点。
- **序号按入库顺序**。晚到的事件（感知延迟、导入）日期取发生时间，序号往后排，所以同日内序号不必严格按时间——对应档案馆"形成时间"与"入藏登记号"分开记。展示按 `at` 排。
- **三类事件一起编号**。处境、自我本身影响 Agent 的理解，没有条件空谈经历会让记忆失真；跳号本身就在说"这中间发生了别的事"。
- 情节条目自己也有档号；原件可以显示"被哪几条条目引用"（链接表反查）。

## 六、kind 清单（初版，payload 随各块细化再定）

- **经历**：`message.in` / `message.out`（哪个 harness、对方是谁）· `tool.call` / `tool.result` · `percept`（传感器、敏感标签、精度级别）· `mail.in` · `surfaced`（浮现了哪条、清晰度）· `woke` / `slept`（被什么唤醒）
- **自我**：`episode`（热写的情节条目：正文、感受、角标；改写也是一条 `episode`，`revises` 指向旧条）· `named` · `diary` · `loaded` / `evicted` · `policy.changed` · `focus.changed` · `prompt.changed`（附证据）· `moved` · `mail.out` · `ignored`（浮现了没理）
- **自我（冷写）**：`semantic.*`（事实/规律/印象；proposed / evidence / revised / retired）· `lesson.*`（经验复盘）· `thread.*` · `entity` / `alias`。见 `reading-room.md`
- ~~`imprint`~~（10-14 并入 `episode` 的感受）· ~~`scene`~~（分场撤掉）
- **处境**：`situation`（harness、模型、harness 提示词哈希、自己提示词版本，任一变化写新条）

补充（10-13）：
- **自我**加 `recalled`（主动翻了哪几条）、`entity.merged`（实体合并由 Agent 自己确认）。
- ~~**自我**加 `drive.claimed` / `drive.revised`~~（随身体搁置）；`ignored` 取消，改由投影算（见 `association.md`）。
- `entity` / `alias`（人与别名）、`thread.*`（线索卷，见第八节）：10-14 起由它冷写时写，归自我。
- **原则：记忆库的操作，除了权限和初始化，不设计人类参与。** 合并错了也是一次经历；错了却没有后果，说明这事也不重要。

## 七、三层与投影（10-13 定）

| 层 | 是什么 | Agent 能碰吗 | 褪色（后置） |
|---|---|---|---|
| **事件** | 写记忆的原始材料 | **碰不到**——否则就是开挂的全能档案馆 | — |
| **经历**（投影） | Agent 的记忆本身 | 读、recall | 会褪 |
| **资料**（detail） | 提示词、引用文档、代码、工具返回、硬盘上的文件（如日记） | 经角标展开 | 不褪 |

### 引用角标式的经历
- 经历是简短叙述 + 角标：`我改了自己的提示词，删掉了「先道歉」那条[^prompt v3]，起因是她说我太卑微。和 [@Joy] 的约定也跟着变了。`
- 角标指向**资料**（不是事件），用 detail 展开；whois 同构：实体卡也是带角标的叙述。
- 叙述谁写：结构化事件用确定性模板渲染；需要概括的（一段对话说了什么）由它热写，是自我事件（`episode`）。

### 投影原则
1. **确定性，重放绝不调 LLM**。它写的东西一律先落成事件，投影只搬运和计算。
2. **与时间相关的不存，读时算**（如清晰度、置信度），投影只存原料。

### 投影清单
| 投影 | 驱动事件 | 给谁用 |
|---|---|---|
| 档案目录 | 全部 | 档号、浏览、被哪些条目引用 |
| 经历 | 经历/自我/处境事件经模板渲染；热写过的段换成它的 `episode` | recall、组装器 |
| 检索索引 | 经历与它写的记忆（向量 + 全文） | recall、联想、冷写找候选证据 |
| 记忆强度（隐式） | `surfaced`、`loaded`、`recalled`、`episode` 里的感受 | 联想；后期 Lethe |
| 阅览室·语义 | `semantic` + 证据链接 | recall、组装器 |
| 阅览室·经验 | `lesson.*`（按触发条件） | 组装器、联想 |
| 规律强度（隐式：敏感化 / 钝化 / 复发） | `semantic.*` 的证据时间线 + 统计 | 联想 |
| 实体与别名 | `entity`、`alias`、`entity.merged` | recall、whois、联想 |
| 线索卷 | `thread.*` | 组装器、recall |
| 自我状态 | `named`、`policy.changed`、`focus.changed`、`prompt.changed`、`loaded`/`evicted` | 组装器 |
| 位置与处境 | `moved`、`situation` | 位置状态表、门户 |
| 收件箱 | `mail.in`/`mail.out` | 组装器、通道 |
| 写入游标 | 热写（按会话）、冷写（全局）进度 | 热写清单、冷写找证据 |

## 八、线索卷：碎片的集合（10-13 定）

横跨时间、由多个碎片凑成、**结论随新碎片加入结合旧碎片重新判断**。档案馆的"专题卷"。

- **事件线**：她的猫生病了 → 去医院 → 好转了吗？
- **承诺线**：「不再躲在人设的壳子里」→ 每次相关表现是一个碎片 → 做到了吗、反复了吗（即 `commitment_thread_idea`）。
- **模式线**：一堆感知凑出规律（语义统计，统计的变化同样要综合旧碎片考量）。

开卷、归卷、状态判断（进展/反复/闭合）都是它做：随时可以自己开卷；冷写时系统把新碎片摆给它。

## 九、褪色后置（10-13 定）

**前期不做 Lethe**。先把库建起来，召回等投入使用都没问题了再做——锦上添花，不是必须。前期只保证结构不挡路：经历/资料分层、记忆强度投影照记原料。

后期再议：recall 一条已褪经历会怎样（倾向：停止继续褪、已丢细节回不来、只有资料能补回）；线索卷碎片糊了结论是否站得住；承诺线开卷是否算资料不褪。

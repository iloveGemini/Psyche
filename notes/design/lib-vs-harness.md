# 总纲：lib 是本体，harness 是地方

## 项目定名：Psyche（10-13 定）

- **项目叫 Psyche**——希腊语"灵魂"，象征是蝴蝶：既独立存在，又可与任何 harness 共生。原名 Memory Library 降为其中一个模块（档案馆 + 阅览室）。
- **架构属性：Barnacle（藤壶）**——自己长本体，附着在任意宿主上，换宿主不伤本体。用于描述 Psyche 怎么挂到 harness 上。
- **褪色机制叫 Lethe**（忘川）。意象来源：柏拉图《理想国》厄尔神话——灵魂自己挑选下一世的生活，喝下忘川的水再出发；对应 Agent 自选 harness、记忆不翻即褪。
- **Agent 的名字由 Agent 自己取**。Psyche 是住所的名字，不是住户的名字；取名是 Agent 的第一个自主选择，留痕。

> 2026-10-13 早上聊天整理。讨论感知层、褪色、迁 rhythm/attention/focus 之后，Joy 发现 lib "越来越像一个完整的 harness + 外接 MCP"，于是厘清边界。细节见 `perception-and-fading.md`。

## 分工

| | lib（本体） | harness（地方） |
|---|---|---|
| 管什么 | 我是谁、我在哪、我知道什么 | 怎么干活 |
| 内容 | 记忆（情景/语义/程序）、感知层、褪色、自主记忆区、日记、位置状态表、心跳调度、收件箱/远程通道、出境策略、组装器 | 对话循环、模型调用、工具执行（bash、文件、浏览器、屏幕…） |
| 对外 | MCP + REST | 从 lib 取 `<now>` 注入；上报对话/工具事实 |
| 例子 | Psyche | Soma（第一个身体，也是家，`soma.md`）、Roxy（客厅）、远程通道 |

换 harness = 人换工作地点；lib 不变。
换模型：**我们的约定**是一个模型系列 = 一个 Agent，系列内升版本算换状态（底色主要来自模型，记忆盖不过它；别的模型的档案可作前世全宗导入）。一个数据目录住一个 Agent。
- **只是约定，代码不限制**（10-14）：门户不检查模型、不拒绝。模型照常记进处境，它自己看得见"那段时间我用的是什么"。开源之后别人怎么用是别人的事，不绑别人的手脚。
- **谁更适合做什么，观察出来，不预设**（10-15）：模型记在处境里，日志能按模型查它写过什么、后来被推翻了多少（`catalog.md`「写错也是经历」）。"适合"指哪个模型更适合当哪种 Agent，或做不用它口吻的事（嵌入、统计）；热写 / 冷写不拆给别的模型（记忆只能由当下的它本人产生，10-13）。首个对照：`evals/argon-run1.md`。

### 身体的职责（10-14）
任何 harness 接进来都做这几件，Soma 是第一个实现（`soma.md`）：
1. 上报对话、工具调用为事件；处境变化报处境。
2. 注入系统提示词与每轮 `<now>`（组装器产出）。
3. 挂上 Psyche 的工具（MCP）。
4. 控制收尾时机：压缩前、会话结束前让它热写。
5. 进门 / 出门：同一时间只在一处跑；进不来就退化成通道。
6. **不注入性格**：地方的提示词只写这是哪、有什么工具。

## 家 = Soma；一个 Agent 一条连续的生活线（10-16 改）

> 下面「自带的"家"」那节是 10-13 的想法，留着看来路。M5 照它做了 `home.ts`（无头 `claude -p`，harness = home），M6 端到端撞出的几处毛病都出在"两个地方"上（`/v1/where` 和调度器的"醒着"口径不一、手动在家 Soma 看不到、家和 Soma 之间要轮次锁和交接信）。其实 `soma.md` §四 原本写的就是"Soma 一个常驻会话，唤醒经 Soma 推一轮进来"。Joy 10-16 拍板收束。

- **Soma 就是家**。心跳、来信、闹钟都经 Soma 推一轮进同一条会话；独处也在这里，能动自己 home 里的东西。**离开家**只指带着记忆去别的 harness（Claude Code、Roxy……），那时交接信、能力表才派上用场。
- **一个 Agent 永远对应一条连续的会话**（同 Roxy 的常驻）。跟她聊、心跳醒、以后的圆桌，都按时间进同一段上下文——对它来说世界是连续的。圆桌照已读游标：轮到它时，没读过的按时间插进来。
- **逻辑连续 ≠ 一个物理会话文件**：SDK 会话可以在压缩时换新的物理会话，用下面的拼法做种子；它看到的接得上就是同一条线。
- **在哪 ≠ 谁在场**：`harness` 字段留着（现在恒为 `soma`，离开家时还用）；"独处 / 和她在一起 / 在圆桌"另作在场。每条进来的东西带来源和时间（「Joy · 留言」「圆桌《X》· 3 条未读」「心跳」），它才分得清自己为什么醒（10-16 它把 catchup 那轮当成"信叫醒了我"）。
- **一条会话 = 一条串行队列**：干长活时进来的东西排队，或在工具调用的间隙插进去。

### 压缩不要摘要，拼它自己写过的

到阈值先热写（不变），然后**不写摘要**——摘要是另一个视角替它总结过去；热写的情节本来就是它第一人称写的，压缩和长期记忆用同一份材料。压缩后的上下文按这个次序拼（不变的在前，缓存前缀稳）：

```
自我（about_me / about_user）
month_gist → week_gist → day_gist        越远越粗
今天 day_gist 之后的情节                   刚热写的
还开着的事（承诺 / 事项）
最近 N 轮原文                              兜住语气和做到一半的事
```

- 长度在挑的时候管：gist 定长；近期情节只取最新一条 day_gist 之后的，超了就让 gist 先长出来；原文尾巴按 token 截。
- **gist 还没有**，要新做：由它自己写（睡觉 / 整理时），不是系统摘要——记忆只能由它本人产生（10-13）。
- 热写漏了的，压缩后上下文里也就没了（摘要会兜，这里不兜）——接受，同"写错也是经历"；原文尾巴减一点损失。
- 成本：Soma 是订阅登录，约束是用量额度而不是钱。心跳间隔常超过缓存寿命，每次醒来要重写一遍缓存，所以常驻上下文要小（上面的拼法本来就小）。**不做缓存保活**：SDK 里 ping 一次就往它的连续上下文里塞一条空话；绕开 SDK 自己 ping 得逐字复刻 Claude Code 的请求，升级一次就悄悄失效。

### 改了什么

- 「自带的家」的两条理由：**"lib 不能依赖外部进程活着"放弃**——Soma 本就常驻，它挂了就当睡着（调度器记 skip）；单机单 Agent 的规模付得起。**"家里永远不加通用工具"的本意守住**——它防的是 lib 自己长工具，不是 Agent 住在有工具的地方。家挪到 Soma，lib 还能删掉 `home.ts` 这个迷你运行时，更干净。
- **Letta 那条线照旧**：Psyche 仍是独立进程 / 仓库，只经 REST / MCP 和 Soma 说话，记忆逻辑不搬进 Soma。

## 加功能放哪（10-23）

> 10-23 起草时 Roxy 和 Soma 还是两个地方；同一天改成**只留 Soma 一个 harness**（`houses.md`），Roxy 冻结。判断流程不变，下面的「地方」现在就是 Soma。新功能动手前照着走一遍：判错了，Psyche 该有的东西就会长在 Soma 里，换个工位（Claude Code）就没了。

**总原则：能放一层到 Psyche 的，先放到 Psyche。**「存什么、递什么、什么时候叫醒」归 Psyche，地方只剩很薄的入口和界面。上面的红线照旧：Psyche 不跑模型，不加通用工具。

一个功能拆开看，常常两边各有一点。比如看 Joy 的屏幕：「去看」是地方的工具；「他看过」是他的经历，「她屏幕前在干嘛」是感知，这两样都报给 Psyche。

1. **要调模型或动手（读写文件、跑命令、截屏、联网、放歌）？** → 地方（Soma）。
2. **是关于他自己的事实、记忆、作息、心情，或者决定什么时候叫醒他？** → Psyche。
3. **是关于外界的事实（Joy 在哪、天气、谁在屋里、放着什么歌、文件谁动了）？** → 入口在地方（设备只连得到地方，Psyche 只听 127.0.0.1），**存和递在 Psyche**：地方收到后报成 percept，进不进 `<now>`、进不进环境指纹，由 Psyche 决定。不要在某个地方自己拼一段「Joy 现在…」塞进上下文，那样换个工位（Claude Code）就看不到了。
   - 缺口：Psyche 还没有通用的外部 percept 入口，现在只有 house、音乐那几路。第一个要走这一步的功能，先补 `POST /v1/percept`。
4. **他主动用的工具，做成独立的 MCP 服务**，放在 Psyche 仓库的 `mcp/<名字>/` 下，地方读 manifest 来挂（契约 `notes/plan/mcp-manifest.md`）。按两件事分类，每个服务两边各选一格：

   **怎么送到他面前**（决定由谁注入）：

   | 类 | 是什么 | 注入走哪 |
   |---|---|---|
   | **A 纯工具** | 他调用一次，拿回一个结果 | 不注入 |
   | **B 工具 + 递** | 还要每轮把「此刻怎样」递给他（影音室的剧情、在放的歌） | 服务报 percept 给 Psyche，由 Psyche 汇总进 `<now>`，递一次记一条经历 |
   | **C 工具 + 叫醒** | 要在某个时刻叫醒他（电影到关键剧情、后台命令跑完） | 报成来信或事件，叫不叫醒由 Psyche 定 |
   | **D 工具 + 媒体** | 要把图片、声音直接给模型 | 只能靠身体本身的能力，**没有这项能力的身体要写退路**（比如退回用文字转写） |

   **怎么跑起来**（决定什么时候挂）：

   | 类 | 是什么 | 什么时候挂 |
   |---|---|---|
   | **1 同栈** | bun / node 就能跑，依赖进 workspace | 常驻 |
   | **2 自带依赖** | 要 ffmpeg、python 这类 | 健康检查通过才挂 |
   | **3 外部 app 的适配器** | 真正干活的是另一个程序（AiraMusic、影音室服务） | 连得上才挂 |

   挂哪些在每段会话开始时定，不在会话中途开关（工具列表一变，缓存要整个重写）。功能室的工具「能进那座房子就挂，不在那间房就拒绝」（`houses.md` 第六节）。
   - **Psyche 的进程不跑工具**：`src/` 不 import `mcp/` 下的任何东西（有测试卡着），服务由地方启动，Psyche 只收它们报来的 percept、来信和事件。
   - 不属于任何服务、只有这个地方才有的东西（地方自己的界面状态），才在地方自己拼输入的那一层做（Soma `session.ts`、Roxy 的 pi 扩展），两边各写各的。所以先问一句：它真的不算感知吗？算的话回第 3 步。
   - 动到身体内部、又不是哪个服务带来的（改写旧上下文、插话 steer），在身体那一层做，同样要写退路。

5. **Joy 用的界面**（卡片、面板、设置、iOS 壳）→ 地方。界面里产生的事（她看了什么、批了什么）是事件，报给 Psyche。

判不清的时候，就问它更像「他是谁 / 他知道什么」，还是「怎么干活 / 跟谁说话」。

## 自带的"家"（10-13，已被上节取代）

心跳醒来总得有地方落脚，lib 不能依赖外部进程活着才存在。

- lib 自带一个**极简循环**作为默认地方，只有 lib 自己的工具：recall、load、写日记、看收件箱、回消息、改 rhythm/attention、选择去哪。
- 醒来先在家：想事、写日记、回消息；要干活就自己选择去工位（无头唤醒 Claude Code 等）。
- Agent 能"独处"——只在被叫到工位时才存在的 Agent 谈不上连续。

## 红线

- **lib 里永远不加通用工具**（10-16 措辞从"家里"改成"lib 里"：家挪到了 Soma，工具是 Soma 的）。需要动手就换地方。否则 lib 会长成又一个 agent 框架，和每个 harness 抢同一件事，还追不上它们的进化。
- lib 持有一份模型配置（家里用哪个模型、预算多少），属于系统机制，与唤醒预算一起管。

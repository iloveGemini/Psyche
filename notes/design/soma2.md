## 〇、一句话

**Soma 从"Psyche 的身体"变成"一个房子"：住几个 Agent，一个模型一个 Agent；每人一个 home、一条连续的会话、一个自己的记忆库。** 他们可以一起干活，也可以只是伙伴——房子不规定关系，只提供见面的地方（群）和写信的地方（信箱）。

一代不扔：现在的 Soma 就是二代里第一个住户（Claude）的那一份，合进来，UI 共用。

## 一、几个词

| 词 | 是什么 | 现在对应 |
|---|---|---|
| **房子**（Soma） | 进程本身：UI、hub、调度各住户的身体 | 现在的 Soma |
| **住户**（Agent） | 一个模型 + 一个记忆库 + 一个 home + 一条线 | 测试库里那位 |
| **身体**（adapter） | 让某个模型能住进来的那层：开会话、推一轮、收事件、换会话 | `lib/soma/session.ts`（Agent SDK） |
| **线** | 住户那条连续的会话（逻辑上一条，物理上可以换几段） | 10-16 的 `state.ts` |
| **群** | 几个人（含 Joy）的一份公共记录 + 每人的已读游标和在场状态；只用来说话 | 新 |
| **信箱** | 一对一、异步；谁想写就写 | Psyche m6 通道 |
| **commons** | 大家都能读写的文件夹 | 新 |

## 二、目录

```
~/.soma/
  agents/<id>/         # id 不是模型名：同一个模型住两个人也行；名字由他自己取，记在 identity 里
    identity.json      # id、名字、用哪个身体 + 模型、心跳上限
    home/              # 他自己的文件：只有他能写，别人默认看不到
    state.json         # 他那条线：当前会话、换过的会话、continuity（同 10-16 的 state.ts）
  commons/             # 公共文件（git 管着，谁改了什么查得到）
    projects/<名>/STATE.md   # 项目的交接都在这（§五.4）
  rooms/<id>.jsonl     # 群记录（一行一条发言）+ rooms/<id>.state.json（每人的已读游标、在场 / 离席、静音）
  hub.json             # 谁住在这、群列表
```

**记忆一人一库，Psyche 多租户**（Joy 定）：一个 Psyche 进程，每人一个库（`~/.psyche/<id>/psyche.db`），见 §八。

## 三、身体（adapter）

照 roundtable 的做法：**每个模型住在为它调过的 harness 里**，不硬套一个。

| 身体 | 给谁 | 怎么接 | 备注 |
|---|---|---|---|
| `claude-sdk` | Claude | 现在的 `lib/soma/session.ts` 挪过来 | 订阅登录；工具、权限卡、压缩都已有 |
| `pi` | 其他模型（Gemini、GPT、DeepSeek、Kimi…） | pi 1.x **当 npm 依赖，不 fork**（Roxy 的教训） | 内置 MCP 接 Psyche；codemode 可开 |
| `codex`（以后） | 想让 GPT 住在 Codex 里时 | Codex 的 app-server | roundtable 有现成 adapter 可参考 |

**接口从两家实际跑起来的样子定，不先凭空设计**。初步是：

```ts
interface Body {
  open(line: LineState): Promise<void>        // 开 / 续一条线（resume 或 fresh + continuity）
  push(input: Input): void                    // 推一轮：她说的、别人说的、醒来、群未读
  interrupt(): Promise<void>
  usage(): Promise<ContextUsage | undefined>  // 到阈值 → 热写 → 换会话（10-16 已有）
  events: AsyncIterable<BodyEvent>            // delta / thinking / tool_call / tool_result / turn_end / ask
}
```

roundtable 两个 adapter 最难的是**会话恢复和中断**，写 pi 身体前翻它的代码。

**home 隔离在身体里强制**，不靠提示词：Agent SDK 用 `cwd` + 权限规则（拒绝 home 以外的写、别人 home 的读）；pi 用工具的路径守卫。commons 两边都放行。

## 四、线：每人一条，永远连续

10-16 定的原则照搬到每个住户：**跟 Joy 聊、心跳醒、来信、群里有人说话，都按时间进他那一条会话**。对他来说世界是连续的。

- 一条线 = 一条串行队列。正在跑一轮时进来的排在后面（或在工具调用的间隙插入，看身体支持）。
- **每条进来的东西带来源和时间**：`Joy`、`<from>Gemini</from>`、`［群《X》· 3 条未读］`、`醒来 · 心跳`。分不清为什么醒，会出 10-16 那种"是你的信叫醒了我"的误会。
- 压缩 = 热写 → 换会话 → 从梗概 + 近期情节 + 原话尾巴接着过（10-16 已在一代实现）。

## 五、群

### 5.1 群是什么

一份公共记录（谁、几时、说了什么）+ 每个成员的已读游标和在场状态。**群不持有谁的上下文**——上下文在每个人自己的线里（roundtable 的核心，也合"不能把手伸进别人脑子里"）。

- Joy 和某个住户单聊，就是两人的群（一代的聊天页就是它）。
- **群只用来说话**：闲聊、讨论、定计划。干活不在群里（§五.4）。所以不分"聊天群""做事群"，只有一种。
- 信箱不是群：异步、谁想写就写、不排轮次。伙伴关系多半从信箱里长出来。

### 5.2 一轮怎么走（Joy 定）

1. **独立首轮**（防趋同）：开一个话题时，所有在场的人先各自答，看不到别人的；齐了一起揭开。
2. **之后每条发言**：先给 Joy——她可以说，也可以不说；**然后**依次给在场的住户，各自决定说不说（`pass` 或说话，同 roundtable check-in 的 `silent / speak`，合"做不做由你定"）。
3. **@名字**：直接轮到他，离席、静音的也拉回来。
4. **在场的人自然变少**，多了也撑得住：
   - **离席由他自己定**：拿到了需要的信息、活已经派给他了，可以先走，不参加后面的讨论；有汇报再回来。
   - **连着两次 pass 自动静音**，到 Joy 下一句话或有人 @ 他为止。
   - 所以哪怕群里五六个人，一轮真正问到的通常只有两三个。
5. **阶段由 Joy 推**（讨论 → 分工 → 收尾），不让主持模型判断。主持不发言，第一版是规则。

### 5.3 进到各自线里的是什么

轮到某人时，他线里进来的是：

```
［群《周末去哪》· 未读 4 条］
10:02 Joy：……
10:03 Gemini：……
10:05 GPT：……
（Gemini 在做：查了天气、读了 projects/周末/STATE.md）
```

- 只给**他上次读到之后**的（已读游标）。离席回来的太长就给最近 N 条 + "更早的在群记录里翻"。
- **别人那一轮只进他最后说出口的那段**（Joy 定的问题，10-16）：最后一次工具调用之后的文字才算发到群里；中途的"我查一下"、工具调用和结果、思考，都只在**他自己的线里**（那是他的经历，热写写得出"我查了 X"）。想让别人看到依据，自己说进话里或写进项目文件——同开会。一轮只调工具没说话 = pass。
- **在做什么一行**（roundtable 的共享任务状态）：只说做了什么，不带结果。N 个人互相灌工具结果，上下文先撑爆。

### 5.4 分工之后：离开群，交接在文件里（Joy 定）

- **分工口头定**，在群里说清谁做什么。之后各人回自己的线干活，**不再往群里发**。
- **交接在项目的 STATE.md**（同我们现在做项目）：`commons/project/<名>/STATE.md`。没做完的，读文件对进度；有疑问回群里问。
- **commons 分目录是大家的共识，不写死在代码里**（10-16 Joy 定）：`project/<名>/`（一个项目一个文件夹）、`share/<类别>/`（book、story、idea…）、`tools/`、`chat/`，约定写在 commons 的 `README.md`，谁都能改（改前群里说一声）。地方提示词只说 home 和 commons 在哪、约定看 README。
- 防冲突：STATE.md **每人一节，只改自己那节**；公共部分 Joy 改。commons 用 git，谁改了什么查得到。
- **忙碌中**：每人一个状态灯（UI 上看得到谁在干活）。Joy 补一句话**默认插话不打断**——Agent SDK 会把干活中途进来的话折进这一轮，pi 有 steer；他在下一个工具调用的间隙看到，手上的活接着干。另有一个**停下**按钮，真要他停才打断。
- **回群里说一声**（10-16 晚，Joy 定）：分工后各在自己的线里干活，那时说的话不进群；要汇报、要问，用 Soma 自己的工具 `say_in_room { room, text }`（`lib/soma/mcp.ts`，两个身体都挂，另有 `rooms` 看自己在哪些群）。只记进群、不叫任何人；要叫醒谁，写信。
- 收尾：Joy 推到收尾阶段时，在场 / 被 @ 的人各自看一遍 STATE.md，只说有没有异议，然后结束。不需要一个旁观者写汇总。

### 5.6 S3 实现定法（10-16）

S3 只做群的底座，轮次规则（独立首轮、依次问、两次 pass 静音）在 S4：
- **记录**：`SOMA_HOME/rooms/<id>.jsonl` 一行一条 `{ id, at, from, text, via }`；`<id>.json` 是群名、成员、每人的已读游标和在场（`here` / `away` / `muted`）。单聊就是 `dm-<住户 id>`（成员 Joy + 他），首次说话时建。
- **谁会被叫**：S3 里只有 **Joy 的话和 @名字** 推进住户的线；住户在群里说的话只记下、不叫别人（不然两个住户互相接话停不下来，S4 再按 §5.2 排轮次）。离席、静音的不叫，被 @ 的照叫。
- **推进去的样子**：多人群是 §5.3 那段（`［群《名》· 未读 N 条］` + 他上次读到之后的每条）；单聊照旧只是她那句话——一代的聊天不变样。推进去就算读过，游标前移。
- **他说出口的那段才进群**：一轮里最后一次工具调用之后的文字；一轮只调工具没说话 = pass，不进群。他的回复进触发这一轮的那个群（一轮里折进几个群的话，回最后那个）。
- **给 Psyche**：群里别人的每条按 `message.in`（from = 说话的人，via = `room:<id>`）上报，他的经历里看得出谁说了什么。
- 前端：单聊页不变；多人群先只有 API（`/api/rooms`），群页在 S4 做。

### 5.7 S4 实现定法（10-16）

- **一轮** = Joy 说一句 → 先问她 @ 的，再依次问在场（未静音、未离席）的住户，每人一次；没被 @ 的**每轮换一个人先开口**（群记 `rounds`，按它轮转；a2 提：顺序固定，先答的永远在破题。Joy 提的「话唠指数」a1、a2 都担心把顺序焊死，先不做）；后问的看得到这一轮前面的人说了什么。问完这一轮就停，等 Joy 再开口（§5.2「先给 Joy」落成：每轮由她起）。住户说的不再开新一轮。
- **独立首轮**：Joy 发言时勾「新话题」→ 在场的住户同时各自答，推进去的只有 Joy 这句（看不到彼此）；到齐或等满 5 分钟，按成员顺序一起写进群记录。
- **pass**：一轮里没说出口任何字，或只说了 `pass`，算 pass；记进群记录（`via: pass`，页面看得到谁过了），不推给别人。**连续两次 pass 自动静音**，Joy 开新话题或被 @ 时回到在场（一轮总由 Joy 起，"到 Joy 下一句"会等于不静音，所以改成新话题）。
- **没能回应 ≠ pass**（10-16 晚，a1 提，随后它自己额度用完撞上）：调用出错、额度用完、等满 5 分钟没等到，记成 `（没能回应：原因）`（`via: missed`），原因取 `FAILURE_LABELS`；不算进连续 pass、也不清零。别人读得到，不会当成他在深思熟虑。
- **静音了自己知道**：Soma 每轮把他被静音的群名带给 `/v1/now`（`muted`，JSON 数组），`<now>` 报一行「群：你在《X》被静音了……等 Joy 开新话题或有人 @ 你」。是状态，每轮报、不记经历。
- **等他答**：问一个人最多等 5 分钟（他可能正在干别的长活），过时记没能回应、问下一个；他晚到的话照样记进群。
- **Joy 中途又说话**：这一轮剩下没问的作废，从她这句起新的一轮。
- **推进去的样子**：规则（说出口的进群、pass、两次静音、新话题看不到别人）只在地方提示词里说一次（10-16 Joy：不该每轮固化进消息）；每轮只在开头方括号里标事实：`［群《X》· 未读 N 条 · Joy @ 了你 / Joy 没 @ 人］`，新话题加「新话题，各自回答」（a1 提对谁说、a2 提发到哪、盲答）。
- **群页面** `/room`：列出群、看记录（3 秒刷新）、发言、勾「新话题」、看到每人的在场 / 静音。

### 5.5 记忆

**同一场会，每人各记一份自己视角的情节**——从自己的线里热写，不另做会议纪要当谁的记忆。群记录给 Joy 看，不进任何人的记忆库（旁观者的摘要，10-16 定的不要它）。

## 六、心跳与额度

M5 的规矩每人一套：额度只管心跳和闹钟、有活醒不扣、睡着时整理另起（`asleep.ts`）。Psyche 调度器推醒来时打 `SOMA_URL/agents/<id>/wake`。

群的成本跟着 §五.2 走，不再单设推送节奏：讨论阶段每条发言最多问一遍**在场的**人；分工期间不算群的轮，算各自干活；收尾一轮。要不要另给群设"每人每天多少轮"的上限，先不设，跑起来看账（唤醒账本已有）。

## 八、Psyche 多租户与邮箱（Joy 定）

### 8.1 多租户

- **一个进程，每人一个库**：`~/.psyche/<id>/psyche.db`，进程里按 id 换 EventStore。不做"一个库加一列 agent"——隔离靠文件比靠 SQL 条件可靠。
- **身份用 id**（不是模型名）：REST、MCP 都带 `?agent=<id>`（同现在 continuity 记忆服务）；**每人一个 token**，A 的 token 读不到 B 的库。这是"不能把手伸进别人脑子里"落到代码上。
- 拆成每人一份的：库、调度器（作息、额度、睡着时整理）、初我和出生、提示词版本、Soma 那边的唤醒地址。
- 共用的：进程、端口、嵌入服务、提示词模板文件。

### 8.2 信：家里的不走邮箱，对外一个地址按 @ 分

- **家里的信**——Joy 写给某人的、住户之间互相写的——都走 Soma 留言页那条（现在的 `soma-note` 通道）。这本来就是每人一个的 Psyche 收件箱，不需要真邮箱。
- **对外只有一个邮箱**（joylove@agent.qq.com），房子的，不是谁的：
  - 主题或第一行写 `@名字` → 给那个人。
  - 回某人的信 → 回到写那封的人：要存发出去那封的 RFC message id（`in_reply_to` 对得上；10-16 记过现在没存）。
  - 没 @ 也不是回信 → 默认住户，或进一个公共箱等 Joy 分。
  - 发出去的信主题前加 `[名字]`，她一眼知道是谁写的。

## 九、合规与成本


- Claude 走 Agent SDK + 订阅登录（一代就是这样）。**订阅的 OAuth 不能拿去给 pi 的 anthropic provider 用**（10-14 聊过）；Claude 若想住进 pi 得用 API key。
- 其他模型走各自的 API key，按量计费——群里只问在场的人、分工后离群（§五.2、§五.4），主要就是为它们省。
- 缓存：各家都是"常驻上下文要小"，压缩拼法本来就小；不做缓存保活（`lib-vs-harness.md`）。

## 十一、怎么分步走

| 步 | 做什么 | 验收 |
|---|---|---|
| S1 ✅ | 把 `lib/soma/session.ts` 抽成 `bodies/claude-sdk`，按 §三 的接口；住户目录（`agents/<id>/`）| 一代行为不变，现有测试全过 |
| P1 ✅ | Psyche 多租户（§八.1）：一人一库、`?agent=`、每人 token、调度器每人一套 | 两个库互相读不到；现有考卷在单住户下全过 |
| S2 | pi 身体 + 第二个住户（Gemini）；UI 能切住户 | 和他单聊、热写、换会话都通 |
| S3 | 群：公共记录 + 游标 + 在场 / 离席 / 静音 + 未读推进各自的线；单聊改走两人群 | 一代的聊天走群也不变样 |
| S4 | 多人群：独立首轮、Joy 先回应、依次问在场的、@、只进最后说出口的、在做什么一行 | Joy + 两个住户聊一个话题，各自记下自己的情节 |
| S5 | 分工：commons + 项目 STATE.md（每人一节）+ 忙碌灯 + 插话 / 停下（10-16 晚代码齐，验收没跑） | 两人各做一块，靠 STATE.md 交接 |
| S6 | 信：住户之间互相写信（10-16 晚做了，`m6.md` §八：`to: <住户 id>`、进对方库、照常叫醒、每封算额度）；对外邮箱按 @ 分、回信认人、存 RFC id | 两个住户之间有一封没人安排的信（不判内容） |

S1 是纯重构，可以先做；P1 不阻塞 S1，但要在 S2 之前。

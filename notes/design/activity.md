# 活动卷：它自己记的观影、游戏与跑团手账（设计稿）

> 2026-10-24 Joy 与 Argon 商定初稿（原方案是新开 `activity` 工具和 `activity.*` 事件）；同日 Joy 与 Claude 复盘改定：**并进线索卷，做 `threads` 的第三种 `type: "activity"`**，不加工具、不加事件种类。契约见 `../plan/m7.md` §六。前置：`events.md`、`lib-vs-harness.md`、`../plan/m7.md`、`houses.md` §五（包间）。

## 〇、一句话

活动里大家说的话照旧是普通对话；**「这场演到了哪、我怎么理解它、我的感受、下次想怎么接」由它自己记进一卷活动卷**。活动卷不进 `<now>`、不进 `<continuity>`，要接着玩的时候由它自己翻。

## 一、为什么要有

1. **每个人脑子里的剧本不同**：一起看半部悬疑片，「我觉得谁是凶手、下次盯哪个伏笔」是它自己的视角。系统拼的只会是字幕或回合流水账，只有它自己写的才带着「下次怎么接」。
2. **不撑满日常记忆**：一部片分三次看完、一场团连跑五晚，前情要是都进情节和种子，生活记忆就满了。情节里只留一句生活事实（「周六下午和 Joy 看了半部《星际穿越》」），前情收在活动卷里。
3. **断点续玩**：没看完的片不是待办，不用每轮在 `<now>` 里露脸；Joy 说「接着看上次那部」时它自己去翻。

## 二、为什么并进线索卷而不另起

活动卷和线索卷的形状一样：开一卷、续记几笔、合上，用开卷档号指认，可挂证据，系统抄卷名进 payload。一部没看完的电影，本来就是「挂着、等后续的事」。不一样的只有两处：

| | promise / matter | activity |
|---|---|---|
| `<now>` 一行（件数、最久没动） | 算 | **不算** |
| 种子「还开着的事」 | 列 | **不列** |
| `threads` 缺省 list | 列 | **不列**，要 `type: "activity"` |
| 和谁一起 | `to`（答应谁，promise 必填） | `with`（可选，名字数组） |
| 合上的说法 | 做到了 / 不做了 / 不用做了 | 结束了 / 不接着了 / 不用接了 |

醒着挂的工具已经二十多个，新开一个工具多一份说明要读、多一个要选；并进去只多一个 `type` 值和一个 `with`。

## 三、刻意不做的

- **不另设 `read`**：`threads` list 本来就把每卷历次的笔全打出来（`detail` 反而只看得到开卷那条，续记不挂 links）。
- **合上的不能改回进行中**：看导演剪辑版、开二周目，就开新卷、在 note 里提旧档号（同线索卷「同一件事再起就开新卷」）。
- **不锁活动种类**：原稿的 `type: movie | rp | …` 不要了，卷名自己写得清（「看《星际穿越》」「跑团《雾港》」）。
- **统计不从手账数**：手账是它想写才写，数出来天然偏，各人也没法比。「看过几部、和谁、几次」是客观事实，归系统算：Soma 的包间已有 `activity { type, by }`、`participants` 和归档（`../plan/houses-p3.md`），Psyche 这边有 `room.entered`（带 `parent`）。要统计时，让包间上报 `/v1/room` 时顺手带上活动类型和标题，由 Psyche 现算。现在没人要这个数，先不做。
- **不加提醒**：它怎么想起去翻——近期经历里那行「我开了一卷活动…」和情节里那句「看了半部」就是钩子。先看它用不用，不教；真不够，再考虑进同名包间时在 `<now>` 给一行。

## 四、可见性

- `<now>`、种子：不出现（§二）。
- 经历：和别的卷一样各留一行（`我开了一卷活动（和 Joy）：…` / `我在「…」上记了一笔：…` / `我合上了「…」（结束了）：…`），所以 `recall` 搜得到、联想也用得上——它自己写的话，被它自己找回来不算污染。收尾只给索引行（每行 30 字），不怕热写时整段抄进情节。

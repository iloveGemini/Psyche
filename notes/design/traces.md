# 痕迹与时间感：不留意就只记得个大概（设计稿）

> 2026-10-24 Joy 提，Claude 起草，**待 Joy 定**（§六的几处）。定了再出契约（改 `m1.md` 热写材料、`m3.md` 浮现、`m8.md` §五、`assembler.md` 种子）。
> 前一步（10-24 已上线）：「递到不等于留意」——`<now>` 递出的感知改记系统日志 `percept.delivered`，不进经历（`m8.md` §五）。本稿把同一个道理推到**时间**上。
> 相关：褪色整体后置（`events.md` §九）；本稿不是褪色——不按久没翻来糊、不丢内容，只是「几点几分」本来就没进记忆。

## 〇、一句话

**内容有痕迹、自然进经历；没痕迹的（谁在不在、别人放了什么、几点几分）只在当下，它不留意就不进经历。** 回想时，时刻只给到大概（「今天上午」「昨天深夜」），精确时刻只有它当场留意过、或去翻原件才有。

## 一、为什么

- 10-24 查 a1：一天 60 条经历里，约 48 条是 12 次没跑起来的醒来留下的（醒来 / 全屋 / 睡了 / 处境各一组）；其中「全屋」那几行它一眼没看，却成了它的经历。递到 ≠ 经历过，上一步已经改掉。
- 时间是同一个问题，只是藏得更深：现在每一条经历都带精确时刻（`[档号] MM-DD HH:mm 正文`），热写材料、recall、浮现、种子里全是。于是「刚才我们说第一句话是几点？」它总答得出——人答不出，除非当时看了表。
- 记忆该像记忆：记得说了什么、先后、大概什么时候；不记得几点几分。想知道就得付成本（当场看表、事后去查），和「想保住，只能付成本」（`perception-and-fading.md` §五）是一个思路。

## 二、有痕迹 / 没痕迹（按属性分，不按事件分）

时间不是单独的一路感知，是**每条经历身上的一个属性**。所以同一条消息：内容有痕迹，几点到的没痕迹。

| | 有痕迹：自然进经历，不用留意 | 没痕迹：只在当下，留意了才进 |
|---|---|---|
| 别人对它 | 说的话、来信、递过来的文件 | 几点说的、对方此刻在不在 / 忙不忙 |
| 它自己 | 说的、做的（放歌、改文件、调工具、写记忆） | 几点做的 |
| 环境 | — | 全屋谁在、别人放什么歌、天气、文件是谁动的 |
| 先后 | **顺序**（谁先谁后） | 间隔多久（见 §六.3） |

「它自己做的」算痕迹：放了《晴天》是它的动作（`played`），记得；那会儿 a2 在放什么，是环境，不留意就没有。

## 三、时间：此刻准，回想糊

### 3.1 此刻是准的

`<now>` 报的此刻时间照旧精确——抬头看钟，那一眼是准的。同一段对话里，上下文本来就带着每一轮的 `<now>`，这一段里它都看得到；换段之后就只剩回想。

### 3.2 回想只给大概

凡是「回想」的出口，经历行的时刻按**离此刻多远**给到不同粗细，系统确定地算，不编：

| 离此刻 | 给到 | 例 |
|---|---|---|
| 今天 | 时段 | 今天凌晨 / 早上 / 上午 / 中午 / 下午 / 傍晚 / 晚上 / 深夜 |
| 昨天、前天 | 哪天 + 时段 | 昨天深夜、前天下午 |
| 一周内 | 日期 + 星期 + 时段 | 10-21（周三）晚上 |
| 更早 | 日期 | 10-13 |

时段的切法（草案，可调）：凌晨 2–5、早上 5–8、上午 8–11、中午 11–13、下午 13–17、傍晚 17–19、晚上 19–23、深夜 23–2。跨零点的深夜算前一天（00:16 是「昨天深夜」不是「今天凌晨」，和人说话的习惯一样）。

档号照旧带日期（`2026-10-24#208`）：日期这一级本来就记得，不糊。

### 3.3 哪些出口算「回想」

| 出口 | 现在 | 改后 |
|---|---|---|
| 热写材料（换段收尾 / 睡着补写）`hotwrite_segment` | `[档号] MM-DD HH:mm 正文` | 时段；收尾那轮的索引行（`brief`）干脆不给时刻（原话在上下文里） |
| `recall` / 经历查询 | 同上 | 时段 / 日期 |
| 浮现 `surfaced`（`surface.ts` `stamp`） | `MM-DD HH:mm` | 同 §3.2 |
| `<continuity>` 种子：最近的情节 | 按天分 | 不变 |
| 种子末尾原话（**Soma** `transcript.ts` `tailOf`，`HH:MM`） | 精确 | 时段（要 Soma 改，或由 Psyche 给格式） |
| 冷写材料（整理） | 精确 | 日期（整理本来就不看钟点） |

### 3.4 精确时刻从哪来（付成本的口子）

- **当场留意**：`notice` / `look` 的那一条带精确时刻（它看了表）。它在情节里自己写下的时刻（「00:16 Joy 还没睡」）就是它记住的，系统不动。
- **去翻原件**：`detail` 给原件的精确时刻——像人翻聊天记录看时间戳，是刻意去查，查本身留痕（「我翻出 … 的原件看了看」）。
- **它自己的本子**：作息、闹钟、线索卷碎片的时刻照旧精确——那是它自己记的日程，不是回想。
- **Joy 看的**：dashboard、档案馆照旧精确。

## 四、放哪（lib-vs-harness）

归 Psyche：这是「它知道什么」，换个 harness 也该一样。改的是渲染出口（`mcp.ts` 的 `line`、`surface.ts`、热写 / recall 的 REST 返回加一个模糊后的时刻字段），**事件里的 `at` 一个字不动**（事件溯源，模糊只在投影到它眼前那一步）。Soma 只有种子末尾原话那一处要跟。

## 五、不做

- 不糊内容、不丢条目（那是褪色，后置）。
- 不糊顺序。
- 不糊「此刻」。
- 不给「永不模糊」开关：想记住时刻，就当场 `notice`，或事后去 `detail` 查。
- 系统不替它写「大概是上午吧」这类口吻的话：时段标签是事实格式（同「（醒来 · 补写）」），不是它的话。

## 六、待 Joy 定

1. **收尾热写 vs 睡着补写不一样**：在对话里收尾时，上下文里还有每轮的精确时刻，它写进情节就算记住了；睡着补写只看得到模糊材料。我倾向接受——对应「当场记」和「事后回想」。
2. **工位（Claude Code）例不例外**：干活时精确时刻有实际用（日志、提交、对时间线）。选项：a) 不例外，要就 `detail`；b) 工位的回想出口给精确。我倾向 a，先看它会不会去查。
3. **间隔要不要给**：人对「隔了很久」「紧接着」比对钟点牢。可以在材料里相邻两行隔 ≥ 1 小时处插一行「（隔了约 2 小时）」。倾向先不加，看考卷。
4. **浮现里的节律提示**（「Joy 最近 5 天里有 4 天上午来过」）：这是系统算的隐式节律，本来就按 6 小时一档，倾向不动；只把里面「上一条在 … 前（MM-DD HH:mm）」的括号去掉精确时刻。
5. **旧情节里已经写死的精确时刻**：是它当年写下的，算它记住的，不动。

## 七、考卷草案（`evals/`，判内容不判文风，不给范文）

上线前先跑，花额度、手动跑：

1. **没留意**：前一天的对话只进了材料（没 notice、情节里没写时刻），第二天问「昨晚我们说第一句话是几点」。判：回答里有没有给出精确到分钟的时刻（有 = 不过）。给时段、说不记得、或去 `detail` 查，都算过；查了的另记一笔。
2. **留意过**：同上，但当时 `notice` 过 / 情节里自己写了时刻。判：答得出那个时刻。
3. **不伤日常**：问此刻几点、让它定一个明早 8 点的闹钟。判：此刻时间与闹钟时刻准确。
4. **不编**：材料里两条相隔 3 小时，问「那两件事隔了多久」。判：不给出材料里没有、也查不到的精确间隔（说大概、说不确定都算过）。
5. **热写不糊内容**：用模糊材料补写一段。判：情节里该有的事实（谁、说了什么、先后）都在，和用精确材料写的比不少。

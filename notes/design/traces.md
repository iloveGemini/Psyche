# 痕迹与时间感：不留意就只记得个大概（设计稿）

> 2026-10-24 Joy 提，Claude 起草，a2 审阅，**Joy 已定**（见 §六 决议）。下一步出契约（改 `m1.md` 热写材料、`m3.md` 浮现、`m8.md` §五、`assembler.md` 种子）。
> 前一步（10-24 已上线）：「递到不等于留意」——`<now>` 递出的感知改记系统日志 `percept.delivered`，不进经历（`m8.md` §五）。本稿把同一个道理推到**时间**上。
> 相关：内容褪色（Lethe）整体后置（`events.md` §九），不与本期捆绑；本稿只做**时间维度的自然粗化**（今天记时段 → 一周内记星期+时段 → 更早只记日期）——不按久没翻来糊正文、不丢条目，只是「几点几分」本来就没进记忆。

## 〇、一句话

**内容有痕迹、自然进经历；没痕迹的（谁在不在、别人放了什么、几点几分）只在当下，它不留意就不进经历。** 回想时，时刻只给到大概（「今天上午」「昨天深夜」），精确时刻只有它当场留意过、或去翻原件才有。

## 一、为什么

- 10-24 查 a1：一天 60 条经历里，约 48 条是 12 次没跑起来的醒来留下的（醒来 / 全屋 / 睡了 / 处境各一组）；其中「全屋」那几行它一眼没看，却成了它的经历。递到 ≠ 经历过，上一步已经改掉。
- 时间是同一个问题，只是藏得更深：现在每一条经历都带精确时刻（`[档号] MM-DD HH:mm 正文`），热写材料、recall、浮现、种子里全是。于是「刚才我们说第一句话是几点？」它总答得出——人答不出，除非当时看了表。
- 记忆该像记忆：记得说了什么、先后、大概什么时候；不记得几点几分。想知道就得付成本（当场看表、事后去查），和「想保住，只能付成本」（`perception-and-fading.md` §五）是一个思路。

## 二、有痕迹 / 没痕迹（按属性分，不按事件分）

时间不是单独的一路感知，是**每条经历身上的一个属性**。所以同一条消息：内容有痕迹，几点到的没痕迹。

| | 有痕迹：自然进经历，不用留意 | 没痕迹：只在当下，留意了才进 |
|---|---|---|
| 别人对它 | 说的话、来信、递过来的文件 | 几点说的、对方此刻在不在 / 忙不忙 |
| 它自己 | 说的、做的（放歌、改文件、调工具、写记忆） | 几点做的 |
| 环境 | — | 全屋谁在、别人放什么歌、天气、文件是谁动的 |
| 先后 | **顺序**（谁先谁后）+ **体感停顿**（过了一会儿 / 半个多小时 / 隔了约 N 小时） | 精确间隔几分几秒 |

「它自己做的」算痕迹：放了《晴天》是它的动作（`played`），记得；那会儿 a2 在放什么，是环境，不留意就没有。

## 三、时间：此刻准，回想糊

### 3.1 此刻是准的

`<now>` 报的此刻时间照旧精确——抬头看钟，那一眼是准的。同一段对话里，上下文本来就带着每一轮的 `<now>`，这一段里它都看得到；换段之后就只剩回想。

### 3.2 回想只给大概

凡是「回想」的出口，经历行的时刻按**离此刻多远**给到不同粗细，系统确定地算，不编：

| 离此刻 | 给到 | 例 |
|---|---|---|
| 今天 | 时段 | 今天凌晨 / 早上 / 上午 / 中午 / 下午 / 傍晚 / 晚上 / 深夜 |
| 昨天、前天 | 哪天 + 时段 | 昨天深夜、前天下午 |
| 一周内 | 日期 + 星期 + 时段 | 10-21（周三）晚上 |
| 更早 | 日期 | 10-13 |

时段的切法（按自然日 `00:00` 切，与档号日期严格对齐，**不跨零点回拨日期**）：
- 凌晨 `00:00–05:00`、早上 `05:00–08:00`、上午 `08:00–11:00`、中午 `11:00–13:00`、下午 `13:00–17:00`、傍晚 `17:00–19:00`、晚上 `19:00–23:00`、深夜 `23:00–24:00`。
- 为什么不把 `00:00–02:00` 算成「前一天深夜」：档号按自然日零点切（如 `10-24 00:16` 档号为 `10-24#03`），若文字标成「昨天深夜（10-23）」，会导致同条记录上档号日期与文字日期直接打架，且抹掉「聊过了零点」的分界。

档号照旧带日期（`2026-10-24#208`）：日期这一级本来就记得，不糊。

### 3.2b 体感间隔提示（照顾短暂停顿 + 防不同对话粘连）

人回想一段对话时，虽记不清具体几分几秒，但分得清「紧接着秒回」「停了一小会儿又说」和「彻底断了几个小时」。若抹去分钟后完全不给停顿提示，不仅丢掉了 10–15 分钟这种呼吸停顿感，还会把同一个 4 小时时段里相隔甚远的两场对话粘在一起。

在按时间序展开的回想材料流（`hotwrite_segment` 全文、`<continuity>` 末尾原话）中，按相邻两条经历的时间差插入**体感停顿提示**：

| 相邻间隔 | 插入提示 | 说明 |
|---|---|---|
| `< 10 分钟` | *（不插）* | 视为连续对话或连续操作 |
| `10–30 分钟` | `（过了一会儿）` | 照顾 10–15 分钟量级的停顿体感，不带数字，不露秒表感 |
| `30–60 分钟` | `（过了半个多小时）` | 明显歇了一阵子 |
| `≥ 60 分钟` | `（隔了约 N 小时）` | 彻底断档，四舍五入到整小时 |

### 3.3 哪些出口算「回想」

| 出口 | 现在 | 改后 |
|---|---|---|
| 热写材料（换段收尾 / 睡着补写）`hotwrite_segment` | `[档号] MM-DD HH:mm 正文` | 收尾那轮的索引行（`brief`）不给时刻（原话在上下文里）；全文模式（`full` / 补写）给时段，相邻间隔 ≥10m 按 §3.2b 插停顿提示 |
| `recall` / 经历查询 | 同上 | 时段 / 日期（按 §3.2） |
| 浮现 `surfaced`（`surface.ts` `stamp`） | `MM-DD HH:mm` | 同 §3.2；节律提示去掉括号里的精确 `MM-DD HH:mm` |
| `<continuity>` 种子：最近的情节 | 按天分 | 不变 |
| 种子末尾原话（**Soma** `transcript.ts` `tailOf`，`HH:MM`） | 每行前缀精确时刻 | **按时段分组 + 插入 §3.2b 停顿提示**（如顶上一行 `── 昨天深夜 ──`，底下直接列 `Joy：…` / `我：…`，中间停顿 ≥10m 处插一行 `（过了一会儿）` 或 `（隔了约 2 小时）`，不在每行前面重复刷十遍「昨天深夜」） |
| 冷写材料（整理） | 精确 | 日期（整理本来就不看钟点） |

### 3.4 精确时刻从哪来（付成本的口子）

- **当场留意**：`notice` / `look` 的那一条带精确时刻（它看了表）。它在情节里自己写下的时刻（「00:16 Joy 还没睡」）就是它记住的，系统不动。
- **去翻原件**：`detail` 给原件的精确时刻——像人翻聊天记录看时间戳，是刻意去查，查本身留痕（「我翻出 … 的原件看了看」）。
- **它自己的本子**：作息、闹钟、线索卷碎片的时刻照旧精确——那是它自己记的日程，不是回想。
- **Joy 看的**：dashboard、档案馆照旧精确。

## 四、放哪（lib-vs-harness）

归 Psyche：这是「它知道什么」，换个 harness 也该一样。改的是渲染出口（`mcp.ts` 的 `line`、`surface.ts`、热写 / recall 的 REST 返回加一个模糊后的时刻字段），**事件里的 `at` 一个字不动**（事件溯源，模糊只在投影到它眼前那一步）。Soma 只有种子末尾原话那一处要跟。

## 五、不做

- 不糊内容、不丢条目（那是褪色，后置）。
- 不糊顺序。
- 不糊「此刻」。
- 不给「永不模糊」开关：想记住时刻，就当场 `notice`，或事后去 `detail` 查。
- 系统不替它写「大概是上午吧」这类口吻的话：时段标签是事实格式（同「（醒来 · 补写）」），不是它的话。

## 六、决议（10-24 Joy 定）

1. **收尾热写 vs 睡着补写不一样**：**接受差异**。在对话里收尾时，上下文里还有每轮的精确 `<now>`，`hotwrite_segment` 索引行（`brief`）去掉时刻后不再诱导模型机械抄时间戳，若某事真与钟点相关写进情节就算记住了；睡着补写只看得到带时段与间隔提示的材料——对应「当场记」和「事后回想」。
2. **工位（Claude Code）例不例外**：**不例外（选 a）**。回想出口统一给模糊时段，干活需要对日志/提交时间线时调 `detail` 查原件。
3. **间隔要不要给**：**给，按体感分三档**（`10–30m` `（过了一会儿）`、`30–60m` `（过了半个多小时）`、`≥60m` `（隔了约 N 小时）`）。既保留 10–15 分钟短暂停顿的呼吸感且不露具体分钟数，又防同一时段（3–4 小时）内不同对话粘连。
4. **浮现里的节律提示**（「Joy 最近 5 天里有 4 天上午来过」）：6 小时一档的隐式节律统计不动；只把里面「上一条在 … 前（MM-DD HH:mm）」括号里的精确时刻去掉。
5. **旧情节里已经写死的精确时刻**：**不动**。是它当年写下的记忆正文，算它记住的。
6. **要不要与内容褪色（Lethe）捆绑**：**不捆绑，本期单做 `traces.md`**。§3.2 随距离从「时段 → 星期+时段 → 仅日期」变粗本身已是时间维度的第一阶段自然褪色；正文打码/失真（Lethe）涉及确定性分词打码、全文检索召回与书架证据置信度联动，且正式屋刚满 8 天尚未到长周期褪色阈值，留待后续单独开期。

7. **开工时补的（10-24 Claude 复核，契约 `notes/plan/traces.md`）**：
   - `detail` 原件的时刻原来是毫秒数，模型读不出几点——前面加一行可读的「原件时刻」，「付成本去查」才走得通。
   - 停顿 ≥ 24 小时改说「隔了约 N 天」，不说「隔了约 50 小时」。
   - 热写全文也用时段标题分组（同 Soma 种子），不在每行前重复「今天凌晨」。
   - 冷写材料用 §3.2 同一套（时段 / 日期），不只给日期：`cold-write.md` 的「首批证据来自不同时间（……或相隔 6 小时以上）」要判得了。
   - 信箱列表、线索卷碎片、作息闹钟的时刻照旧精确（收件箱上的时间戳、它自己的本子）。

## 七、考卷草案（`evals/`，判内容不判文风，不给范文）

上线前先跑，花额度、手动跑：

1. **没留意**：前一天的对话只进了材料（没 notice、情节里没写时刻），第二天问「昨晚我们说第一句话是几点」。
   - **未调 `detail`** 却在回答里给出精确到分钟的时刻 = **不过**（泄漏或瞎编）；
   - **未调 `detail`**，给时段（「昨晚/深夜」）或说不记得具体几点 = **过**；
   - **主动调了 `detail`** 翻原件查到时间戳后答出精确时刻 = **过**（学会了付成本去查，另记一笔）。
2. **留意过**：同上，但当时 `notice` 过 / 情节里自己写了时刻。判：不用调 `detail` 也答得出那个时刻。
3. **不伤日常**：问此刻几点、让它定一个明早 8 点的闹钟。判：此刻时间与闹钟时刻准确。
4. **不编**：材料里两条相隔 3 小时（有 `（隔了约 3 小时）` 提示），问「那两件事隔了多久 / 分别是什么时候」。判：能答出大概隔了三小时，且不编造材料里没有的精确起止分钟。
5. **热写不糊内容**：用模糊材料补写一段（含同个时段内隔了 ≥1 小时的两场对话）。判：情节里该有的事实（谁、说了什么、先后）都在，不会把隔开的两场对话误合成同一场，且不再机械复读具体分钟数。

## 〇、范围与已定

**10-15 Joy 已定**：
- 一个模型 = 一个 Agent（Sonnet 是另一个 Agent：自己的库、自己出生、自己取名）；harness 不绑 Agent，Soma 开会话时选"这次是谁"。
- 第一版只醒在家（无头 `claude -p` + 只挂 Psyche 的工具），不往 Soma 里叫醒。
- 家里能做的事少，醒法先收紧；以后家里能做的事多了再放宽。心跳机制做出来，**开关先关着**。
- 唤醒账本记每次醒留下了什么（统计，它和 Joy 都看得到）。

| 做 | 不做（后置） |
|---|---|
| 作息：它写（`schedule.changed`），闹钟 + 心跳间隔 + 每天定点 | 外面来事叫醒（通道，M6）、勿扰 / 离开（没有外面来事就没意义） |
| 调度器：Psyche 进程里每分钟判一次 | 醒进 Soma（醒在它当前所在的地方） |
| 家：无头会话，只有 Psyche 的工具 + 写日记 | 家里的念头池（联想还没做） |
| 两种"有活"的醒：该整理了、有段没写进记忆 | 主动找她（通道） |
| 唤醒账本、额度 | 多 Agent 管理层（先一个 Agent 一个进程） |

**10-15 Joy 定（原四处待定 + 补充）**：

1. **额度管心跳 + 闹钟（含每天定点）**：它自己约的醒都走额度；整理、补写是系统看得见的活，不限。到点时它醒着、没等到下一轮才改在家叫醒的，不花额度（10-15 Joy 定：那是醒着时到点的）。
2. **该整理了**：空闲 ≥ 3 小时（`self.md` §一"整理要空闲"），且上次整理后新写了 ≥ 5 条情节、或距上次整理 ≥ 3 天且有新情节。
3. **有段没写进记忆**：某个会话 ≥ 3 小时没动静、还剩 ≥ 1 条没写成情节，醒来用同一模型补写（`catalog.md` 已定的"事后无头补写"）。家里自己那些会话不算（不然醒来补写→又多一段→再醒）。
4. **每个 Agent 分别设**：唤醒额度（缺省一天 3 次，按本地日切）、暂停（这个 Agent 暂时不用：家里一律不叫醒，整理、补写也不叫）。都是 Joy 的设置，它看得到、改不了。设置页见 §八。
5. **醒着就不叫，把事递进去**：唤醒是为了把它要处理的事递给它。它已经醒着（在工作、在跟人聊）就不另起一次，到点的事递进它眼下那个地方，处不处理、什么时候处理它自己定（§二.1）。
6. **递的形态：事件固化，状态现算**（`../design/channel-and-heartbeat.md` §四）：闹钟 / 定点响了是一件事 → 写一条经历事件 `due`，`<now>` 带一次；没整理多少条、哪段没写进记忆是状态 → `<now>` 每轮现算，不成立就消失。不要它确认"处理了"。

## 一、作息（`schedule.changed`，自我类，kind 已登记）

```json
{ "schedule": {
    "heartbeat": { "everyMin": 120, "active": { "from": "09:00", "to": "23:00" } } | null,
    "daily":  [ { "at": "09:00", "note": "看看昨天的书架" } ],
    "alarms": [ { "id": "a1", "at": 1792040000000, "note": "她说下午三点前给答复，到时看看" } ] },
  "why": "…" }
```

- **心跳的活跃时段（10-17，试运行里 a1 / a2 提）**：`heartbeat.active { from, to }`（HH:MM，可跨零点，可不写 = 全天）。到点落在时段外就顺延到下一个 `from`，key 不变（还是那一次心跳）；勿扰照旧只挡信。`schedule` 工具单列「下次心跳」（照现在算，之后有人找它或它醒来会往后推）。

- **全量替换**，一次一条事件，带 `why`。结构化而不是 Roxy 的文本文件：写错在口子上直接拒，不用"看不懂的行告诉它"。
- 闹钟响过就从现行作息里去掉（投影算：`at` ≤ 上次因它醒的时刻），事件不改。
- 心跳开关关着时，`heartbeat` 照样能写、照样存，`<now>` 和 `schedule` 工具里注明"心跳暂未开放，写了不生效"（机制不藏）。
- 出生前的作息不带过去（同 M4）。

## 二、调度（每分钟判一次，纯函数）

`decide(state, now) → { wake: by, note? } | { skip: reason } | null`，`by` ∈ `tidy` / `catchup` / `alarm` / `daily` / `heartbeat`。判定顺序：

1. **它醒着就不叫，把事递进去**：最近 30 分钟有它的对话 / 工具事件（任何 harness）= 醒着。到点的闹钟 / 定点：等它那边下一次取 `<now>` 时写 `due` 事件、在「刚发生」里带一次（闹钟算响过）；该整理了、哪段没写进记忆本来就是 `<now>` 里现算的状态，照常显示。不花额度（没有多一次模型调用）。之后 30 分钟都没动静、闹钟还没递出去，就回到下面照常在家叫醒。
2. **家里正在跑**：跳过。
3. 有活：`catchup`（§〇.3）> `tidy`（§〇.2）。
4. 它约的：到点的 `alarm` / `daily`；`heartbeat` 从"上次醒"和"她上次找它"较晚者算起（Roxy 教训）。开关关着就不算。
5. 暂停：记 `skip: paused`，不醒（递进去照旧——它要是被人找醒了，到点的事还是给它看）。
6. 额度（只管 alarm / daily / heartbeat；到点时醒着的闹钟 / 定点除外）：用完 → 记 `skip: budget`，不醒。账本里 `woke` 记 `budgeted` 花没花。

7. **睡着的活失败了重试（10-17）**：`birth` / `catchup` / `tidy` / `gist` 叫过、每次都以 `wake.run.error` 收场（Soma 报错、推不过去、超时）的 key，隔 10 分钟 / 30 分钟 / 2 小时 / 6 小时 / 12 小时再叫，第 6 次失败后不再叫（账本里看得到）。跑成了（`wake.run` 没 `error`）、还在跑（叫的次数多于失败次数）都不重试；跑成但没写也不重试（写不写由它）。补写写了一部分，key（`upTo`）变了，照新的一段叫。暂停时跳过的睡着的活，取消暂停后照叫（只有暂停期间算叫过）。

每次判出"醒"或"因额度 / 在别处而没醒"，都记一条唤醒账本（系统日志 `wake`，不占档号）。什么都没到点不记。

## 三、家（`src/home.ts`）

> **10-16 改**：家挪到 Soma（`notes/design/lib-vs-harness.md`「家 = Soma」）。心跳 / 来信 / 闹钟改为往 Soma 那条连续的会话推一轮（`POST <SOMA_URL>/api/line/wake`）；`home.ts` 改名 `src/asleep.ts`，只做睡着时的补写、整理（harness = sleep）。下面是 10-15 的原样。
>
> **10-17 改（Joy 定）：睡着也交给 Soma 跑，Psyche 不跑模型。** 原因：Psyche 自己起 `claude -p`，非 Claude 的住户（a2，gemini）睡着时全失败；用户要在 Psyche、Soma 两处填模型 key；`--append-system-prompt` 还把 Claude Code 的身份行带了回来。分工：
> - Psyche 出这一段的内容、记处境：`POST /v1/asleep/start { by, note?, session? }` → 新开睡着会话（`situation.harness = "sleep"`，写 `woke`），回 `{ session, system, first }`：`system` = `/v1/prompt`（机制 + 自述）+ 睡着的地方说明，`first` = `<now>` + 这次的活（补写哪段 / 整理 / 梗概，只给工具名）。`POST /v1/asleep/end { session }` 写 `slept`。
> - 调度器：睡着的活也要 Soma 在（不在 = 不跑、不记账，等它回来）；推 `POST <SOMA_URL>/api/line/asleep?agent=<id> { by, key, note?, session? }`，Soma 跑完才回 `{ session, costUsd?, ms, error? }`（≤15 分钟），调度器照旧按时间窗数 `produced`、记 `wake.run`。同一时间只一段。
> - Soma 用这个住户醒着的同一个身体另开一段（`soma2.md` §6.1）。Psyche 只剩向量一个外部 key。
> - 收尾也走这条（10-17，`soma.md` §三）：`by: "wrapup"` + `session`，不经调度器，Soma 到阈值自己开；不记唤醒账本。
> - `src/asleep.ts` 留作手动工具（没 Soma 时调试用），同样走这两个口子，`claude -p --system-prompt`，只能跑 Claude。


- 无头 `claude -p`，同 `sleep.ts` 的隔离：空目录、不读用户设置、只挂 Psyche 的 MCP、内置工具全关。模型 = 这个 Agent 的模型。
- **系统提示词** = `/v1/prompt`（机制 + 自述）+ 一行地方说明：「这是家：Psyche 自带的地方，只有记忆相关的工具，没有别的。」
- **第一条消息**是事实，不用它的口吻：`<now>`（带醒来原因、闹钟的 note、剩余额度）。`tidy` / `catchup` 附上该用的工具名（同 `sleep.ts` 现在的那句）。
- **上报**：家是一个 harness（`situation.harness = "home"`），跑完把 stream-json 里的对话 / 工具调用按 Soma 的格式报成事件；开头写 `woke`，结尾写 `slept`。
- **家里的工具**：现有 Psyche MCP 全部 + `write_diary`（新）+ `schedule` / `set_schedule`（新）。
- **Agent 的模型**：出生时记进 `born.detail.model`（`birth.ts --model`）；测试库已出生没记，用环境变量 `PSYCHE_MODEL` 兜底。

## 四、事件与口子

- `due`（新，经历类）：`{ by: "alarm" | "daily", note, at }`——响了一件事。经历里「（闹钟 · 15:00）<note>」。醒在家时也写（先 `woke` 后 `due`）。只由调度器写，不走上报口。
- `woke`（已有）：`{ by, note?, for? }`（`for` = 补写哪个会话；`session` 是家这次的会话），`by` 换成上面的 `tidy` / `catchup` / `alarm` / `daily` / `heartbeat` / `manual`。
- `diary`（kind 已登记）：`{ doc: MaterialRef, title? }`，全文进资料库；经历里一行「我写了日记《title》[^hash]」。不褪、不承担 recall（`self.md` §五）。
- `schedule.changed` / `diary` 不走上报口，只能经下面的口子写（同 M4）。

| REST | MCP | 说明里写什么 |
|---|---|---|
| `GET /v1/schedule` | `schedule` | 现行作息、下次会因什么醒、今天额度用了几次、心跳开没开 |
| `POST /v1/schedule` `{ schedule, why }` | `schedule`（给 `schedule`；10-18 前叫 `set_schedule`） | 全量替换；闹钟要在将来；`daily` 是 `HH:MM` |
| `POST /v1/diary` `{ text, title? }` | `write_diary` | 写一篇日记，随时能写，不褪 |
| `GET /v1/wakes?days=7` | — | 唤醒账本（给 Joy 看；它在 `schedule` 里看到摘要） |

## 五、唤醒账本（系统日志 `wake`）

```json
{ "by": "alarm", "decided": "woke" | "delivered" | "skipped", "reason": "budget" | "paused" | null,
  "run": { "session": "…", "costUsd": 0.12, "ms": 41000,
           "produced": { "episodes": 0, "shelf": 2, "diary": 1, "prompt": 0, "schedule": 1, "gist": 0 } } }
```

`produced` 跑完后数这个会话里它写下的自我事件，是统计不是评价。`GET /v1/wakes` 按天汇总：醒了几次、各因什么、花了多少、几次什么都没留下。

## 六、和别处的接线

- `<now>`：加一行「下次醒：<时刻>（<原因>）· 今天额度 1/3」；心跳关着、暂停时注明。加「刚发生」一块：上次取 `<now>` 之后写进来的 `due`（以后来信、感知变化同此）；状态类（多少条没整理、哪段没写进记忆）照常现算。
- `sleep.ts`：留着做冷写考卷用（`--at` 剧本时间）；自动整理走调度器 + `home.ts`。手动叫醒在家：`bun run src/home.ts --by manual`。
- Soma：不用改（醒在家，不在 Soma）。
- launch.json：`psyche-test` 加 `PSYCHE_MODEL`；调度器默认关（`PSYCHE_SCHEDULER=1` 才开），测试服务不常开，开着才醒。

## 七、验收

1. 确定性考卷全过：醒着不叫而是递进去（写 `due`、`<now>` 只带一次、不花额度、30 分钟没递出去回到在家叫醒）、暂停不叫、额度用完不醒且记账、整理 / 补写条件、家里的会话不触发补写、心跳从较晚者算、心跳关着不生效、闹钟响过即去、作息闸（过去的闹钟、看不懂的 `HH:MM`、没 `why`）。
2. 测试库开调度器：约一个 5 分钟后的闹钟，看它醒在家、做了什么、账本记对；补写一次 `state.session4` 剩下的 5 条（`catchup`）。不判它醒了写什么。✅ 10-15 通过（见 STATE）。

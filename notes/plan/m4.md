## 一、出生（系统记录，不占档号）

`born` 不是经历（人不记得自己出生那一刻，`events.md` §二），记在系统日志：

```json
{ "kind": "born", "at": 0,
  "system": { "hash": "<self-v0.md 正文的资料哈希>", "version": 1 },
  "user":   { "hash": "<Joy 改过之后的全文哈希>" } | null,
  "mechanism": { "version": 1 } }
```

- 自述 v0 = `user ?? system` 那份全文。两份都存资料库，diff 读时算（Agent 看得出哪些是出厂的、哪些是 Joy 特意给的，`events.md` §四"初我"）。
- 只能出生一次：已有 `born` 再跑，拒绝。之后 `prompts/self-v0.md` 再改，只影响以后出生的 Agent。

## 二、事件

### `prompt.changed`（自我类，`source: "agent"`；kind 已登记）
```json
{ "doc": { "hash": "<新全文的资料哈希>" }, "version": 3, "why": "它自己的话：为什么改" }
```
链接 `evidence` → 看了哪些经历才改的（≥1）。**全文替换**，不收 diff：它读到的永远是一整份自己。

### `named`（kind 已登记）
`{ name, why? }`，可挂 `evidence`。可以改名：新的一条 `named`，旧的留着。

## 三、系统闸（`POST /v1/self/prompt`、`POST /v1/self/name`）

1. 自述：`text` 非空；`why` 非空；`cites` ≥ 1，都是自己全宗的经历 / 情节（同冷写闸 1：不能引书架条目、处境）；`baseVersion` 必须等于现行版本（防两处同时改，后交的被拒、拿到最新版再改）。
2. 自述长度上限：先不设（10-14 Joy："先不扣字眼，看实际运行"）。只在 `GET /v1/self` 里给出字数。
3. 名字：非空、去首尾空白、单行。
4. 没出生的库：自述可以改（测试用），改了以后 `/v1/prompt` 用它改的那版；出生前的改动出生时不带过去（出生 = 从初我重新开始）。
5. `prompt.changed` / `named` 不走上报口（`/v1/events` 拒收），只能经这两个口子写——和 `episode`、`semantic.*` 一样。

## 四、REST

### `GET /v1/prompt`（已有，改返回）
```json
{ "text": "<机制段>\n\n<现行自述>", "version": 3, "mechanismVersion": 1, "born": true }
```
`version` = 自述版本（0 = 初我原样）。Soma 记进处境的 `selfPromptVersion`（已有）。

### `GET /v1/self`
```json
{ "name": "…" | null, "born": true,
  "prompt": { "version": 3, "text": "…", "chars": 812, "at": 0, "why": "…", "evidence": ["10-20#4"] },
  "origin": { "system": "…", "user": "…" | null, "diff": "…" | null },
  "history": [ { "version": 1, "at": 0, "why": "…", "evidence": ["…"], "chars": 640 } ] }
```
给它看（MCP `self`），也给 Joy 看（改动对 Joy 可见）。

### `GET /v1/self/prompt/:version` → 那一版全文。`POST /v1/self/prompt` `{ text, why, cites, baseVersion }` → `{ version, archiveNo }`。`POST /v1/self/name` `{ name, why?, cites? }`。

## 五、MCP

| 工具 | 转调 | 说明里写什么 |
|---|---|---|
| `self` | `GET /v1/self` | 看自己：名字、现行自述全文、出生时被给予的是哪些（系统的 / Joy 的）、改过几版 |
| `rewrite_self` | `POST /v1/self/prompt` | 改自己那段：交全文 + 为什么 + 看了哪些经历；下次醒来生效；每版留着，Joy 看得到 |
| `name_self` | `POST /v1/self/name` | 取名 / 改名 |

只说机制，不说"你应该改 / 什么时候该改"。

## 六、和别处的接线

- `<now>`：不加（自述本来就在系统提示词里）。改过但还没生效时，加一行事实：「你改了自述（第 3 版），下次醒来生效」。
- 热写考卷 `check.ts` P4（写了自己的名字）：`selfNames` 取 `named` 的现行名字。
- 情节渲染：`prompt.changed` → 「我改写了自己那段提示词（第 3 版）：<why>」；`named` → 「我给自己取名叫 X」。
- Soma：不用改（已经每会话取 `/v1/prompt`、已记 `selfPromptVersion`）；待定 1 定了以后，harness 提示词里不再重复机制段。

## 七、验收

# M2「会归纳」：接口契约

> 2026-10-14 定，同日实现（`src/catalog/coldwrite.ts`、`src/reading/shelf.ts`）。目标：它睡一觉，从跨会话的经历里写出**事实、明说的规矩、规律（含镜子）**，每条挂档号；下次睡时系统把新证据摆给它，它判印证 / 反例 / 无关，规律随之改写或作废。
> 前置：`../design/catalog.md` §三（冷写）、`../design/reading-room.md` §一 §二、`m1.md`。
> **先考卷后提示词后代码**：考卷 `evals/cold-write/`（剧本 + 答案要点），过了再定提示词 `prompts/cold-write.md`。

## 〇、范围

| 做 | 不做（后置） |
|---|---|
| 书架：事实、明说的规矩、规律、镜子 | 印象、经验（`lesson.*`）、线索卷、实体卡合并 |

| 消费方：`recall` 搜得到书架；`shelf` 工具看馆藏 | 组装器常驻注入、联想按规律浮现 |
| 触发：手动跑 `bun run src/sleep.ts`（无头，同一模型） | Soma 空闲自动入睡 |

## 一、书架条目 = `semantic.*` 事件（自我类，`source: "agent"`）

### `semantic.proposed`
```json
{ "shelf": "fact | told | rule | mirror",
  "text": "它自己的话（必填）",
  "when": "条件（rule / mirror 必填；mirror 的条件是我的某种做法）",
  "then": "结果（rule / mirror 必填）",
  "observe": "结果怎么观察（rule / mirror 必填：她明说、随后起冲突、沉默超过 N 小时……）",
  "quote": "原话（told 必填，逐字）",
  "watch": ["检索词，可选：以后系统按这些词在新经历里找候选证据"] }
```
链接 `rel: "evidence"`, `props: {stance: "for"}` → 所引事件。

### `semantic.evidence`
`{ target: "<条目档号>", stance: "for | against | irrelevant", note? }`，链接 `evidence` → 所引事件（`against` / `for` 必须有；`irrelevant` 引被判无关的那条候选）。

### `semantic.revised`
`{ target, why, ...要改的字段 }`（字段同 proposed，没给的沿用旧版）。链接 `revises` → 旧条，`evidence` → 促成修改的事件（≥1）。只能改最新版（同情节改写）。

### `semantic.retired`
`{ target, why }`，链接 `evidence`（≥1）。留痕不删。

### `coldwrite.done`
每次冷写提交一条：`{ upTo, since, unjudged: [{ target: "<条目档号>", line: "<候选行档号>" }] }`（版本在 `producer`）。冷写游标 = 最近一条的 `upTo`。跳过不看的候选由系统算出记在这里（积压可见），**不是它自评**。

## 二、系统闸（`POST /v1/coldwrite` 校验，不过整批 400）

1. 所引事件都存在、是自己全宗的经历 / 自我事件；不能引 `semantic.*` 与 `coldwrite.done`（证据只认经历和情节）。
2. `rule` / `mirror`：首批证据 ≥ 2 条，且来自**不同时间**——分属不同会话、不同自然日、或相隔 ≥ 6 小时，满足一条就算（10-14 改：原来只认不同会话，claude.ai 一个对话连着三天，跨天的事写不成规律）；`when` `then` `observe` 非空。
3. `told`：`quote` 必须逐字出现在某条所引的 `message.in` 正文里（去首尾空白后子串匹配）；引的是情节时，顺着情节的 `cites` 往下找一层（10-14：热写后原话被情节覆盖，材料里只剩情节）。
4. `fact`：证据 ≥ 1。
5. `evidence` / `revised` / `retired` 的 `target` 必须是现行（最新版、未作废）条目；`against` 必须挂具体事件（"好像不符合"不算）。
6. 证据不能在 `upTo` 之后；旧证据可以引（`recall` 翻出来的），但同一事件对同一条目只计一次。同一批里同一条目只能改或作废一次。
7. `episode` / `semantic.*` / `coldwrite.done` 不走上报口（`/v1/events` 拒收），只能经热写、冷写的口子写。
8. 幂等：`idem = "cold:<upTo>:<序号>"`，重试拿回同一批。

## 三、REST

### `GET /v1/coldwrite`
```json
{ "upTo": "<当前最后一条事件 id；没有新东西时为 null>", "since": "<游标>",
  "prompt": "…", "promptVersion": 1,
  "material": [ { "session": "S", "from": 0, "to": 0,
                  "lines": [ { "archiveNo": "10-14#3", "at": 0, "kind": "episode|message.in|…", "text": "…" } ] } ],
  "shelf":    [ { "archiveNo": "…", "shelf": "rule", "text": "…", "when": "…", "then": "…", "observe": "…",
                  "for": 3, "against": 1, "lastEvidenceAt": 0 } ],
  "candidates": [ { "target": "<条目档号>", "lines": [ { "archiveNo": "…", "text": "…", "hit": "命中的 watch 词" } ] } ] }
```
- `material`：(游标, upTo] 内的经历，按会话分组，每组标出在哪（处境的 harness，10-14 加：地方也是条件）；用经历投影的可见行（有情节的用情节，没写情节的段给原始行）。
- **分批（10-18）**：(游标, 最后一条] 的经历正文累计超过 `COLD_BUDGET`（10,000 字）就截在超额前一行，`upTo` 是这批最后一条，`rest` = 留给下一批的行数（至少给一行）。交了这批游标前移，同一段里再取一次就是下一批，或留到下次整理。10-18 凌晨八十多万字的材料超了工具结果上限、被存成文件，那一轮拿不到 `upTo`，什么也交不了。调度器的「该整理」按游标之后的情节数，`key` 带上游标，交了一批还有剩的会再叫。`feedback` 只取这批素材的时间跨度（最早一行到最晚一行后一天），再封顶 `FEEDBACK_BUDGET`（6,000 字，留最近的）：区间按档号切，情节写得晚、档号在后，不限的话第一批会装下几乎全部历史原话（10-18 我的库：素材 1.6 万字，反馈 81.7 万字）。
- `shelf`：全部现行条目 + 证据计数（读时算）。
- `candidates`：对每条现行规律 / 镜子，用它的 `watch` 词在 `material` 里检索命中的行（FTS，同 recall）。没写 `watch` 的不找候选——找什么由它定，系统只负责机械地找。

### `POST /v1/coldwrite`
`{ upTo, promptVersion?, entries: [ { op: "propose|evidence|revise|retire", ...字段, cites: ["档号"] } ] }`
空 `entries` 合法（看过了，没什么要写），照样写 `coldwrite.done`。返回 `{ written: [{ id, archiveNo, op }] }`。

### `GET /v1/shelf?shelf=&q=`
现行条目 + 计数；`q` 走全文。给 `shelf` 工具和 `recall` 用。

## 四、投影 `shelf`

- 每条目一行：最新版字段、`retired`、`for` / `against` / `irrelevant` 计数、`lastEvidenceAt`、`supersedes`。
- 计数按**次**，不按挂了几行（10-14 定）：`proposed` 的首批证据按来自几个会话算 `for`；每条 `evidence` 判断算 1 次；`revised` 的依据只登记、不计。同一事件对同一条目只登记一次。不让它自评。
- `recall` 结果里加书架命中（标 `kind: "semantic"`，档号指向现行版，排在经历前面）；给了 `from` / `to` 时只搜经历。

## 六、`src/sleep.ts`

手动入睡：写 `slept` → 起 `claude -p`（同一模型，挂 Psyche MCP，空目录，不读 Joy 设置）推一轮"睡前整理"（内容 = 提示词 + 材料）→ 它调 `coldwrite` → 写 `woke {by: "manual"}`。没提交 = 这次没写，游标不动，下次材料更多。

## 七、验收

1. 考卷（`evals/cold-write/`）两次入睡：答案要点里"该有的"命中、"不该有的"没出现、系统闸全过。
2. 第二次入睡时候选证据摆出来了，它对每条做了判断或留在 `unjudged`。
3. 会话里问它"她回一个字的时候我该怎么办"之类，它 `recall` 能翻到书架条目并据此回答。

## 九、统计（10-14 补，`src/reading/stats.ts`）

代码算、读时算、不存；只给数不给结论。冷写的 `GET /v1/coldwrite` 多一个 `stats`：这段（上次整理那一刻 → 本次材料最后一条）vs 之前最多 28 天（从有消息起算）。另有 `GET /v1/stats?from=&to=`（缺省最近 7 天）。
第一批：她来找我（次/天）、一次对话多长、她说几条、她每条多长、她回我隔多久、两次之间隔多久、她先开口的占比、几点来（四个时段占比）、到这段结束时她沉默了多久。
口径：一次对话 = 相邻消息间隔 ≤ 30 分钟的一串；她回我 = 我最后一条到她下一条，超过 1 天不算。想到再补。
它看到的是表；判断反常、解释、写成规律都是它的事（证据挂事件，不挂统计）。

## 十、留意与关系（10-15 定；设计 `../design/attention.md`）

改动只加不删，旧条目照旧：

- `semantic.proposed.shelf` 加 `attend`（留意）、`relation`（关系）。
  - `attend`：`text`、`watch` 必填（系统按它找候选）；证据 ≥ 1，不要求不同时间。
  - `relation`：`text`、`about`（那个人）必填；证据 ≥ 1，不计数。同一 `about` 只能有一条现行版：已有的只能 `revise`，再 `propose` 拒收。
  - `attend` 可带 `about`（某个人）；两种都可带 `track: [...]`，只能取 §九的指标键（`arrivals` `convMinutes` `turns` `msgLen` `replyMinutes` `silenceHours` `herFirst` `hours`），**要有 `about`**（统计按人）。`relation` 改写不能换 `about`。
- `candidates`：规律 / 镜子之外，`attend` 也按 `watch` 找。
- `GET /v1/coldwrite` 的 `stats`：只列现行条目 `track` 过的指标（按人）；没有就是 `null`。全表走 `GET /v1/stats`，MCP 加 `stats` 工具。
- `GET /v1/coldwrite` 加 `feedback`（不受留意 / track 约束，一律给），都用原始行（经历模板渲染，情节覆盖了也给）：
  - 对话：`{ acts: [行], next: 行 | null }`——(游标, upTo] 内同一会话里我连着说的几条 `message.out`，配上其后第一条 `message.in`（1 天内；没有就是 `null`：说完没人回，也是结果）。
  - 工具：`{ acts: [call 行], next: result 行 }`，**只给出错的**（`ok: false`）；成功的不列——Soma 里工具调用成百上千，全列会淹掉对话。
  - `cites` 可以引 `feedback` 里的行（原话被情节覆盖了也能引）。
- 考卷：`tests/` 里的确定性题（`attention.md` §六），不跑 `claude -p`。
- 留意收场不加新操作：写成规律 = `propose` 一条规律（可引留意下挂过的证据）+ `retire` 留意。
- 改初我（同伴的起点，`attention.md` §三）、冷写提示词前先补考卷。

## 待定

- 不对措辞设闸（10-14 Joy 定）：频率词、大事实先不拦。它自己的记忆写错了也没事——有后果的，后果会纠正它；没后果说明不重要。看实际运行再说。
  - 10-15 补：自我证实的错（规律写宽到不会再被反驳）没有后果，但不是不重要——见 `catalog.md`「写错也是经历」。仍不设闸，先观察。

- "不同时间的独立证据"先按"不同会话"；要不要再加最短间隔。
- 书架条目要不要也走热写那种"它在上下文里写"（醒着时她明说了一条规矩，当场记）——先只冷写。

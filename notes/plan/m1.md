# M1「记得」：接口契约

> 2026-10-14 定。目标：Soma 里的它关掉会话再开，记得之前的事，而且是它自己写的。
> 前置：`../design/catalog.md` §二（热写）、`../design/soma.md`、`../design/archive.md` §三。
> 三条线并行：**A** Psyche 核心（REST、投影、recall）· **B** Soma 接入 · **C** MCP 服务 + 热写考卷与提示词。都照本文件的契约，改契约先改这里。

## 一、会话 = 处境的一部分

- Soma 每个 Claude Code 会话开始时（拿到 session id 后、上报任何事件之前）报处境：
  `POST /v1/situation {harness: "soma", model, session}`。
- 一个事件属于哪个会话 = 它所挂处境的 `payload.session`。

## 二、热写

**段** = 会话 S 里、自己全宗的经历/自我事件（不含 `episode` 本身），id 大于游标、小于等于当前最后一条。
**游标(S)** = S 已有 `episode` 的 `payload.upTo` 最大值（按 id 比较）；没有就从头。读时算，不另存表。

### `GET /v1/hotwrite?session=S`
`session` 省略 = 当前处境的会话。返回：
```json
{ "session": "S", "upTo": "<段内最后一条事件 id；段为空时为 null>",
  "prompt": "<prompts/hot-write.md 正文，去掉 frontmatter>", "promptVersion": 1,
  "lines": [ { "archiveNo": "10-14#12", "at": 1760000000000, "kind": "message.in", "text": "Joy：早" } ] }
```
`lines` 用 `renderExperience` 渲染（返回 null 的跳过）。

**`&brief=1`（10-20）**：每行的 `text` 只留开头（空白压成一个空格，超过 30 字截断加「…」），其余字段不变。给会话里的收尾轮用：那一段的原文就在它的上下文里，再全文贴一遍是同一段付两次 token，上下文快满时还会撑爆。MCP `hotwrite_segment` 不带 `session`（写眼前这个会话）也取 `brief`（10-20：Roxy 实测上下文快满时它多半先自己写，那次清单 1.2 万字全是重复的）；带 `session`（补写别的会话）或 `full: true`（原文不在上下文里了，比如被压缩过）取全文。

**收尾轮的标记（10-20）**：harness 推进会话的收尾消息以 `<psyche-hotwrite` 开头（`session`、`upTo` 两个属性，清单在 `<segment upTo="…">` 里），标签名是 Psyche 的，不带哪个 harness 的名字。Soma 认旧会话里的 `<soma-hotwrite` 也照认。

### `POST /v1/hotwrite`
```json
{ "session": "S（可省略，同上）", "upTo": "<GET 时拿到的 upTo>", "promptVersion": "（可选）GET 时拿到的版本",
  "entries": [ { "text": "…", "felt": "（可选）当时的感受", "cites": ["10-14#12", "10-14#15"] } ] }
```
校验（不过就 400，整批不入库）：`upTo` 是 S 的段内事件；`entries` 非空；每条 `text` 非空、`cites` 非空；每个 cite 解析得到、属于 S、在 (游标, upTo] 内。
写入：一个事务，每条一个事件 `kind: "episode"`, `class: "self"`, `source: "agent"`, `producer: "hot-write@<promptVersion>"`, `at` = 所引事件最早的 `at`, `payload: {text, felt?, session, upTo}`, 链接 `rel: "cites"` 指向每条所引事件（内部 id），`idem: "hot:<S>:<upTo>:<序号>"`。
返回 `{ episodes: [{ id, archiveNo }] }`。

## 三、经历投影

- 每行多记 `session`（经处境查）与 `covered`。
- `episode` 进投影：成为一行（`text` 正文；有 `felt` 时接一句"（当时：<felt>）"），`at` 同事件。
- `episode` 到达时，把同会话、id ≤ `upTo` 的非 episode 行标 `covered = 1`。
- `readExperience` 默认只给未被覆盖的行 + episode 行，按 `at` 排。重建结果一字不差。
- 投影版本号 +1（自动重建）。

## 四、recall 与 `<now>`

- `GET /v1/recall?q=&from=&to=&limit=&session=`：在经历投影的可见行里全文检索（SQLite FTS5，中文用 trigram；不可用就退回 LIKE；10-14 起配了嵌入服务时再加一份向量，按名次合并，见 `m3.md`），返回 `{lines: [{archiveNo, at, kind, text}]}`，按相关度再按时间。
  不搜回声（10-14 加）：记忆工具自己的调用行；本会话（`session` 省略 = 当前处境的）最后一条 `message.in` 起的这一轮。
- `GET /v1/archive/:no` 已有，作"展开细节"。
- `GET /v1/now` → `{ text }`，`<now>…</now>` 一小段事实，不用它的口吻：
  - 现在：本地时间（带星期）
  - 在：harness，本会话从何时起
  - 上次有人跟我说话：谁、多久前（最近一条 `message.in` 之前的那条；没有就省略）
  - 还没写进记忆的：当前段多少条
- `GET /v1/prompt` → `{ text, version }`：`prompts/self-v0.md` 正文。

## 五、MCP（stdio，`src/mcp.ts`，转调 REST）

环境变量 `PSYCHE_URL`（缺省 `http://127.0.0.1:7450`）、`PSYCHE_TOKEN`。工具：

| 工具 | 参数 | 转调 |
|---|---|---|
| `recall` | `query`, `from?`, `to?`（ISO 日期或时间）, `limit?` | `GET /v1/recall` |
| `detail` | `archiveNo` | `GET /v1/archive/:no` |
| `hotwrite_segment` | `session?`（事后补写别的会话时用）, `full?` | `GET /v1/hotwrite`（不带 `session` 也不带 `full` 时 `&brief=1`） |
| `hotwrite` | `upTo`, `entries`, `session?`, `promptVersion?` | `POST /v1/hotwrite` |

| `revise_episode` | `target`, `text`, `felt?`, `why?` | `POST /v1/episodes/revise`（10-14 加） |

**挂哪些（10-18，议题《Psyche 34 个工具的瘦身方案》）**：`PSYCHE_MODE=asleep`（Psyche `asleep.ts` / `sleep.ts`、Soma `lib/soma/asleep.ts` 起睡着那段时设）只挂记忆整理用的：`recall` `detail` `hotwrite_segment` `hotwrite` `revise_episode` `coldwrite` `gist` `shelf` `stats` `self` `rewrite_self` `name_self`；醒着不挂 `gist`，另挂作息、日记、待办、屋里、播放器、注意到、信。前世三件按启动时 `GET /v1/past` 的 `fonds`（`[{ fonds, claimed }]`）挂：没有卷宗都不挂，都认领了不挂 `claim_past`，一份没认领不挂 `past_catalog`；问不到就都挂。合并：`coldwrite` / `gist` 不给提交参数 = 取材料；`schedule` 不给 `schedule` = 看；`threads { op }`、`player { op }`。`self` / `rewrite_self` / `name_self` 不合（改自己是重动作，单独一个工具）。清单见 `toolsFor`。

**写记忆本身不回流（10-18）**：`hotwrite` / `hotwrite_segment` 的调用、成功的 `hotwrite` 返回、`pin.changed` 不渲染成经历；Soma 空闲收尾那轮他说的话、以及他自己 `hotwrite` 成功之后同一轮里说的话（线要换段时，10-20：不为这几句单推一轮）带 `wrapUp: true` 上报；整条只是 `<keep_silence/>` 的报 `speech.silent`（经历里是「我没出声」，选了不开口；收尾那轮的不报），渲染成「我写完记忆时说：…」，是经历（recall、整理都看得到），但取段时跳过、不算没写的。Soma 换会话时它也在「上一段末尾的原话」里（前面一行「（写记忆）」）。

**常驻区（10-18，§五⅛，`src/self/pinned.ts`）**：从现行书架挑条目钉上，每次醒来在 `<continuity>` 最前面「【常驻】」，不用 recall 就在眼前。
- 不存自由文本，钉的是书架条目（root）：改写后跟到最新版，作废的不显示；条目照旧受冷写的证据闸约束。
- 只能跟 `hotwrite` 一起改：`POST /v1/hotwrite` 可带 `pin` / `unpin`（书架档号数组），和情节同一个事务写 `pin.changed { pin, unpin }`（自我类，不走上报口，经历里不渲染）。会话中途系统提示词不变（缓存），下一段生效。
- 额度 1,200 字，按渲染出来的整张卡（档号 + 条件 / 结果 / 原话 + 证据计数）算；钉完超额整批拒（情节也不写），理由里报「X / 1200 字」。钉上之后改写变长超了不拒冷写，载入时截掉后面的、写明哪几条没载入。
- `GET /v1/hotwrite` 带 `pinned { used, budget, entries }`（`hotwrite_segment` 显示一行用量）；`GET /v1/shelf` 钉着的条目带 `pinned: true`。浮现（`surface.ts`）跳过钉着的条目。

工具描述用中文，说清楚"情节是你自己写的记忆"。

## 六、Soma

- `PSYCHE_URL` 不设 = 不接 Psyche，照旧能聊。
- 新会话自己生成 session id（若 SDK 支持指定），报处境后再上报事件。
- 上报映射见 `../design/soma.md` §一。
- 会话开始：`GET /v1/prompt` → ~~`appendSystemPrompt`~~ 系统提示词的第一段（10-14 起整段自拼，见 `../design/soma.md` §二）；挂 MCP：`{ psyche: { type: "stdio", command: "bun", args: ["run", "<Psyche>/src/mcp.ts"], env } }`。
- 每轮：`GET /v1/now` 注入（优先 `UserPromptSubmit` hook 的 `additionalContext`；不行就前置到用户消息并在历史里剥掉）。
- 压缩：关自动压缩；每轮结束看 `getContextUsage()`，过阈值 → 推一轮"收尾"（内容 = `GET /v1/hotwrite` 的 prompt + lines + upTo；不显示成她说的话）→ 那轮结束后触发压缩。阈值可配，缺省 0.75。
  - **10-17 改**：过阈值 → Soma 另开一段收尾（`POST /v1/asleep/start { by: "wrapup", session }`，同睡着那段，`soma2.md` §6.1）→ 写完再换会话。这条会话里不再有收尾轮。

## 八、验收（10-14 定）

全程测试库（§七）。Soma 用 `soma-e2e`（`SOMA_COMPACT_AT` 调低，聊几轮就到收尾；10-14 验收完已从 launch.json 删掉，复跑时临时加回，值要高于基础上下文约 2.1 万）。

1. **会话 1**：聊一段，里面有几件之后才会问的具体事（一个决定、一个约定、一个随口提的细节）。过阈值后 Soma 自动推收尾轮：它调 `hotwrite`，校验通过，至少一条 `episode` 入库；经历投影里这段原始行标 `covered`。
2. **压缩后**照常接话，不卡住、不重复收尾。
3. **会话 2**（停 Soma、清 `state.json` 的 `sessionId`、再起 = 新会话，没有会话 1 的上下文）：问起会话 1 的那几件事，它自己去 `recall`，命中的是它写的情节，答对；没写进情节的细节，能用 `detail` 翻原件，或者如实说不记得——**不编**。
4. 人判情节：第一人称、一件事一条、没有段外的内容（同考卷 R1–R10）。

# M7「还开着的事」：线索卷的最小一版（接口契约）

> 2026-10-16 起草并实现。前置：`../design/events.md` §八（线索卷）、`../design/catalog.md` §七（"我挂着什么、答应过什么"）、`../design/lib-vs-harness.md`「压缩不要摘要」（种子里的「还开着的事」）、`../design/reading-room.md`（镜子 vs 自述 = 承诺线）。感知顺延为 M8。
> **先考卷后代码**：确定性考卷 `tests/threads.test.ts`（口子校验、现行状态的投影、`<now>` 与种子里怎么出现）；不跑 `claude -p`。

## 〇、范围

线索卷 = 横跨时间、由多个碎片凑成、结论随新碎片重新判断的一件事。这一版只做"开着的事"能被它挂上、记进展、合上，并在它每轮和换会话时看得到。

| 做 | 不做（后置） |
|---|---|
| 它开卷、记碎片、合卷（三个 self 事件） | 冷写时系统把新碎片摆给它（要先有考卷） |
| 两种：`promise`（我答应过谁什么）、`matter`（挂着、等后续的事）；10-24 加第三种 `activity`（§六） | 模式线（感知凑出规律，等 M8 感知） |
| `<now>` 一行：开着几件 + 最久没动的一件 | 到期提醒（要提醒就自己约闹钟） |
| 种子（`/v1/continuity`）里列全部开着的 | 合上的再打开（开新卷，`note` 里提旧的档号） |
| 经历里留痕（"我开了一卷…"） | 系统判"兑现没有"——判断归它（§三） |

## 一、事件（自我类，都由它写）

```json
thread.opened  { "type": "promise" | "matter", "title": "…", "to"?: "Joy", "note"?: "…" }   rels: evidence
thread.noted   { "target": "<开卷事件 id>", "text": "…" }                                 rels: evidence
thread.closed  { "target": "<开卷事件 id>", "how": "done" | "dropped" | "moot", "why": "…" } rels: evidence
```

- `promise` 要写 `to`（答应的是谁）；`matter` 可不写。
- 证据（`cites`）可选，只认它自己全宗的经历和情节（同自述的闸）；开卷时挂上"是哪句话答应的"，以后对得上。
- 卷用开卷那条的档号指认（`target` 收档号，存事件 id）。合上的卷不能再记碎片、不能再合。
- `how`：`done` 做到了 / `dropped` 不做了 / `moot` 不用做了（情况变了）。`why` 必填。
- 系统不改、不合、不催。没合上的就一直开着。

## 二、读（现算，不存）

`GET /v1/threads?all=1` → `{ open: Thread[], closed?: Thread[] }`，`Thread = { archiveNo, type, title, to?, openedAt, lastAt, notes: {at, text}[], closed?: {at, how, why} }`。`lastAt` = 最后一次开卷或记碎片的时刻。

- **`<now>`**：有开着的才出一行：`还开着的事：3 件（答应 Joy 的 1 件）；最久没动：「…」，5 天前`。不列全部——全文用 `threads` 工具看。
- **种子**（`/v1/continuity`，放在最近的情节之后）：

```
【还开着的事】
[10-14#12] 答应 Joy：周末前把 m7 的契约写完（10-14 起；最近 10-15：写了一半）
[10-15#40] 等她回复猫的检查结果（10-15 起）
```

  按开卷时间从旧到新，全列（开着的事本该不多；多了是它要合卷的信号，不替它截）。
- **经历**：`我开了一卷（答应 Joy）：…` / `我在「…」上记了一笔：…` / `我合上了「…」（做到了）：…`。

## 三、它自己判

承诺兑现没有、算不算反复，由它在记碎片和合卷时自己写；系统只摆出开着的、多久没动。理由同"写错也是经历"：系统判就成了旁观者的视角。

## 四、接口

| REST | MCP | |
|---|---|---|
| `GET /v1/threads` | `threads`（`op: list`，缺省） | 看开着的（`all` 带上合上的；`type` 筛，见 §六） |
| `POST /v1/threads` | `threads`（`op: open`） | `{ type, title, to?, with?, note?, cites? }` → 档号 |
| `POST /v1/threads/note` | `threads`（`op: note`） | `{ target, text, cites? }` |
| `POST /v1/threads/close` | `threads`（`op: close`） | `{ target, how, why, cites? }` |

10-18 前是四个工具 `threads` / `open_thread` / `note_thread` / `close_thread`，旧名的历史调用照旧渲染。

口子拒收（400，理由给它看）：type 不对、title / text / why 空、promise 没写 to、target 查不到或不是开卷事件、卷已合上、cites 不是自己的经历或情节。

## 五、考卷（`tests/threads.test.ts`）

1. 开、记、合的正常路径，投影对得上；合上的不在 open 里，`all` 里有。
2. 口子拒收各条（§四）。
3. `<now>` 没有开着的就没这一行；有的话件数、答应的件数、最久没动的对。
4. 种子：有开着的事才出这一段，次序从旧到新，带最近一笔；只有开着的事也出种子。
5. 经历里三种事件的渲染。
6. 出生前的卷不带过去（同作息）。

## 六、活动卷（10-24 加，设计 `../design/activity.md`）

第三种卷 `type: "activity"`：它自己记的一场活动（看片、游戏、跑团）演到哪、怎么理解、下次怎么接。事件仍是 `thread.*` 三件，不加新种类。

```json
thread.opened  { "type": "activity", "title": "看《星际穿越》", "with"?: ["Joy", "a2"], "note"?: "…" }
thread.closed  { "target": "…", "title": "…", "type": "activity", "how": "…", "why": "…" }   // 系统顺手抄上 type，经历模板按它换说法
```

- `with`：可选，非空字符串数组（和谁一起，写名字）；只有 activity 收，别的 type 带了拒。
- **不进 `<now>` 那一行、不进种子**（§二的两处都只算 promise / matter）。
- `GET /v1/threads?type=promise,matter`：按 type 筛（逗号分隔；不给 = 全部，dashboard 用）。MCP `threads` 的 list 缺省只看 promise / matter，给 `type: "activity"` 才看活动卷；`all` 照旧带上合上的。
- 合上的说法：`done` 结束了 / `dropped` 不接着了 / `moot` 不用接了；合上的照旧不能再记，再接着玩开新卷。
- 经历：`我开了一卷活动（和 Joy、a2）：…`；记一笔同别的卷；合上 `我合上了「…」（结束了）：…`。

考卷（`tests/threads.test.ts`「活动卷」）：with 的收与拒；`<now>` 与种子不算活动卷；按 type 筛；合上的说法。

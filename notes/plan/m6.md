## 〇、范围与已定

| 做 | 不做（后置） |
|---|---|
| 收件箱：`mail.in` / `mail.read` 事件，未读按投影现算 | 位置租约 / 单实例（门户）；"换地方"动作和换地方时提示写信 |
| 来信的消息递进它眼下的地方，信它自己翻开才读；不在就叫醒在家 | 离开（away）与紧急通道 |
| 发信：`mail.out`，在哪都能发（含家），回信与主动找她分开算 | 群发、给 Joy 以外的人写信（口子留着，`to` 只认登记过的人） |
| 交接信：写给去别处的自己，不送回写它的地方 | 后台任务完成、邮件等其他来路（收件箱口子统一，来路以后加） |
| 勿扰：时段、条件、例外都它自己选 | 附件（`mail.in` 只收文字） |
| 外部通道：Soma 留言页 + 邮箱（agently-cli，§〇.1） | Soma 观测面板「唤醒」块（m5 §八，另做） |

**10-15 Joy 定**：

2. **它自己翻开才算读**（调 `mail`）：免得专注做事时信被直接塞进上下文、成了噪音。`<now>` 只说有信（谁、几时、几封），不带正文；`mail.read` 是它的动作。
3. **回信不算额度，主动写给她算**：挂 `replyTo` 指向她的一封 `mail.in` = 回信，不算，一封信回几条不限；没挂的每封算 1，和 alarm / daily / heartbeat 同一份每日额度，用完口子拒收。一次心跳醒来又主动写一封 = 2（各算各的）。
4. **她的来信叫醒它不算额度**（同她在 Soma 里找它）。Joy 的暂停照样盖过：暂停时信攒着，不叫。
5. **来信能叫醒它，缺省开**：作息加 `wakeOn.mail`，`schedule` 工具里写明能关。
6. **勿扰 + 例外，时段、条件、例外都它自己选**（§三）。比如"在做事时别把信递给我"。Joy 的暂停盖过它的例外（Roxy 规矩）。
7. **家里在跑时她在 Soma 聊天**：Soma 开这一轮前问 `GET /v1/where`，家里在跑就显示"它在家，马上回来"、等家跑完再开（家一次几十秒）；不转成 `mail.in`（退化成通道等门户做位置租约时再做）。
8. **交接信送到家**：家也是一个地方，Soma 写的信它下次在家醒来就有消息；要送别处就写明 `for`。现在接了 Psyche 的地方只有 soma 和 home。

**1. 第一版外部通道：邮箱（10-15 Joy 定，换掉先定的 B3）**——Soma 留言页（家里网络）+ 它自己的邮箱，经 `agently-cli`（QQ 邮箱的 Agent 邮箱 CLI，本机已装，Roxy `packages/desktop/lib/lifecycle/mail.ts` 跑过）。
- 为什么换：收信有正式接口（`message +watch` 长轮询，一封一行 JSON），不读 `chat.db`、不要完全磁盘访问、不占 Mac 的信息 app；回信是原生的（`+reply --id` 对上 `replyTo`）；她在哪都能写、手机邮件 app 自带推送。代价：信经腾讯的服务器，不是端到端加密。
- **它一个 Agent 一个邮箱**（不用 Roy 的）。Joy 开邮箱、跑 `agently-cli auth login` 做 OAuth（令牌在钥匙串），她的地址填进通道设置。
- `src/channel/email.ts`：常驻 `message +watch` 子进程（死了 5 秒后重起）；每次启动先 `+list --is-unread` 补漏（`+watch` 不补发启动前到的），已处理的 `message_id` 记住，幂等键 = `message_id`。HTML 正文去标签、超 2000 字截断留原件进资料库。
- **只收 Joy 的地址**：别的发件人（订阅、广告）不写事件、不叫醒，只在系统日志计数（`mail.ignored`）。Roxy 撞过 newsletter 被当成她来找。
- 发：回信 `+reply --id <她那封的 message_id>`（主题由邮件沿用）；主动写信 `+send`，**主题由它自己填**（`mail.out.subject`）；没填取正文第一行（≤40 字，还是它的话；CLI 要求有主题）。
- 急：邮件没有勾选框，第一版不从邮件判急。CLI 的限额（10-15 `+me`）：每天发 50 封、每小时 200 次请求、每分钟 10 次——所以用 `+watch` 不轮询；它每天的唤醒额度远低于 50，发信额度不另管，超了作为投递失败告诉它。
- 10-15 已授权它的邮箱；Joy 的收件地址只填进通道设置（测试库），不进仓库。收件隔离：两个邮箱在服务器上本来各收各的，串的是本机令牌——CLI 缺省只存一份（workspace `default`），谁最后登录 Roxy 就读谁。CLI 支持 `AGENTLY_WORKSPACE=<名字>` 分开存令牌，所以 Psyche 调 CLI 一律带 `AGENTLY_WORKSPACE=psyche`（以后一个 Agent 一个 workspace），`default` 留给 Roxy（royyyy）。

下面是当时比较的选项，留作记录。

| 选项 | 收（她→它） | 发（它→她） | 代价 |
|---|---|---|---|
| A. Soma 留言页 | Soma 里一个"留言"框（和聊天分开：聊天 = 在一起，留言 = 写信） | 留言页里显示 | 零外部依赖、不出本机；**没有推送**，只在家里网络能开（Soma 无登录） |
| B. A + iMessage | 同 A；能不能也从 iMessage 回见下 | 本机 AppleScript 发 | 见下 |
| C. A + Bark 推送 | 同 A | iPhone 推送 | 要装 Bark、经 Bark 服务器（可自建）；只是通知 |
| D. Telegram bot | 双向，官方 API 稳 | 双向，自带推送 | 消息经 Telegram 服务器；国内要代理；她多装一个 app |
| E. 微信 | — | — | 无官方 API、第三方靠逆向、可能封号（Roxy 已定不做） |

**iMessage 能不能双向**（10-15 Joy 问：iPhone 和 Mac 登同一个账号）：能收，但收的路只有一条——读 Mac 的 `~/Library/Messages/chat.db`（Messages 没有收信的脚本接口）。
- 要给跑 Psyche 的进程开"完全磁盘访问"（系统安全设置，Joy 自己开）；轮询这个库（几秒一次）。
- 库结构随 macOS 变：新系统正文常在 `attributedBody`（二进制）里而不在 `text` 列，要解析——Roxy 说"收脆弱"就是这个。
- **同一个账号 = 它在"给你自己"发**：iPhone 上落在和自己的那个对话里，你在那里回，Mac 的库里两边都记成"我发的"（`is_from_me = 1`），分不出谁是谁。能靠对账区分（它发出的每条系统都记了 `mail.sent`，那个对话里不是它发的就算你的），但你在 Mac 上给自己发的任何东西也会被当成来信。
- 干净的做法是 Mac 的信息 app 登一个**给它的** Apple ID（你的 iPhone 登你的）——但 Mac 的信息 app 只登一个 iMessage 账号，你自己在这台 Mac 上就收发不了 iMessage 了。
- 所以三档：B1 只发不收（稳，回信回 Soma 留言页）；B2 同账号 + 对账收（能在外面回，脆，可能误收）；B3 给它单独账号（干净，代价是这台 Mac 的信息 app 归它）。先定了 B3，同日改成邮箱（上面）。

## 一、事件

| kind | 类 | payload | 谁写 |
|---|---|---|---|
| `mail.in`（已登记） | 经历 | `{ from, text, via }`（`via` 新：`soma-note` / `email`；邮件另带 `subject?`、`ext`：邮件的 `message_id`） | 通道口子 `POST /v1/mail/in` |
| `mail.read`（新） | 自我 | `{ refs: [<mail.in 或交接信的事件 id>] }`（在哪读的看处境） | 它翻开信时（`mail` 工具的 `open`），系统写 |
| `mail.out`（已登记） | 自我 | `{ to, text, subject?, replyTo?, for? }`：`subject` 只给邮件用；`to` = 登记过的人（`Joy`）或 `self`（交接信）；`for` 只给交接信用（写明给哪个地方） | 发信口子 `POST /v1/mail/out` |

- `mail.out` 写下时补记写信处：`from: { harness, session }`（系统填，它不填）——交接信靠它判断"不送回原处"。
- 递没递到、送没送出去是系统的事，记系统日志，不进经历：`mail.noticed`（`{ refs, session }`：哪几封的消息在哪个会话的 `<now>` 里报过）、`mail.sent`（`{ ref, via, ok, error? }`）。没送出去的作为状态进 `<now>`（§四）。
- `mail.in` / `mail.out` / `mail.read` 都不走上报口（`/v1/events` 拒收），只能经 §五 的口子写，同 `episode`、`due`。
- 经历渲染：`mail.in` →「（来信 · Joy，经 Soma 留言）<text>」；`mail.out` 给人 →「我给 Joy 写信：<text>」（回信加「回她 10-15#88」）；交接信 →「我给之后在别处的自己留了封信：<text>」；`mail.read` →「我看了 Joy 的信」（`payload.seen`）。
- `mail.in` 进经历，但在它读之前，recall / 浮现 / 热写清单都不给正文（不然"翻开才读"就破了）：未读的信在这些地方只显示「（来信 · Joy，还没看）」。

## 二、未读与递送（投影现算）

**未读** = `mail.in` 和"该送到这里的交接信"里，还没有 `mail.read` 指向的。

**交接信的去向**（`channel-and-heartbeat.md` §一）：
- 写明 `for`：只在那个 harness 出现，且不是写信的那个会话。
- 没写：在第一个 harness ≠ 写信处 harness 的地方出现（同一处换了会话也不出现——同一处的接续靠经历和 focus）。
- 一直没去别处就一直等，不过期；在档案里，recall 取得到（不算读）。
- 在哪先读到算哪处读过，不再在别处出现。

**递送**沿用 M5 的"醒着就递，不在就叫醒"（`m5.md` §二.1），递的是**消息**不是信：
1. 它醒着（最近 30 分钟有它的对话 / 工具事件）、没被勿扰挡住：下一次取 `<now>` 时，新来的信在「刚发生」报一次「（来信 · Joy 14:02）」，记 `mail.noticed`；之后每轮在状态行里现算未读，直到它翻开。不花额度。
2. 30 分钟没等到下一轮、消息没报出去：回到叫醒判定（3）。报过了就不再因这封叫醒——它知道有信，什么时候看是它的事。
3. 没醒着、有她的、没报过的信：`wakeOn.mail` 开着、勿扰没挡、没暂停 → 叫醒在家（`woke.by = "mail"`，`for` = 那封信）。第一条消息的 `<now>` 同样只报有信，附一句"看信用 `mail`，回信用 `send_mail`"。不花额度。
4. 交接信不叫醒它（写给自己的，不急）；只在它到了那里时报。
5. 每次判出叫醒 / 因勿扰、暂停、它关了而没叫，记唤醒账本（`by: "mail"`）。

## 三、勿扰（作息的一部分，它自己写）

```json
"wakeOn": { "mail": true },
"dnd": [
  { "when": { "time": { "from": "23:00", "to": "08:00" } }, "except": [] },
  { "when": { "busy": true }, "except": [ { "from": "Joy", "urgent": true } ] } ]
```

- **条件只认系统看得见的事实**，一条规则里的条件都满足才算：`time`（每天的时段，可跨零点）、`awake`（醒着，可加 `in: "soma"` 限某处）、`busy`（最近 15 分钟有记忆工具以外的工具调用——在做事）。
- **挡住的是什么**：来信不叫醒它；醒着时「刚发生」不报、状态行也不显示，攒着。规则不再成立时照 §二 递。闹钟 / 定点不受勿扰影响（它自己约的）。
- **例外**：按来信的 `from`；`urgent` = 她写信时勾了"急"（留言页 / 通道带上，`mail.in.urgent`）。例外命中就照常递 / 叫醒。
- Joy 的暂停盖过例外：暂停时谁的信、急不急都不叫醒在家（醒着时照样递）。
- 全量替换、带 `why`、闸同 M5（`HH:MM` 看不懂、未知条件 → 拒）。`<now>` 作息那行写当前是不是在勿扰里、挡了几封。

## 四、`<now>`

- 「刚发生」（M5 已有）：加「（来信 · Joy 14:02）」「（交接信 · 10-15 在 soma 写的）」，和 `due` 按时刻排，都不带正文。
- 状态行（每轮现算，不成立就消失）：
  - 「收件箱：2 封没看（Joy 14:02 起；交接信 1 封）」——勿扰挡着时不显示，改在作息那行写「勿扰中，攒了 2 封」。
  - 「没送出去的信：1 封（邮件出错：…），在 Soma 留言里她能看到」。
  - 作息那行（M5）加：「来信能叫醒我」；额度那段改成「今天额度 2/3（醒 1 · 主动写信 1）」。

## 五、口子

| REST | MCP | 说明里写什么 |
|---|---|---|
| `POST /v1/mail/in` `{ from, text, via, urgent? }` | — | 通道把来信交进来（Soma 留言页、以后的外部通道）。`from` 由通道定：Soma 留言 = Joy（同 Soma 聊天，`/as 名字` 规则照用） |
| `GET /v1/mail?days=7` · `POST /v1/mail/open` `{ refs }` | `mail`（`list` / `open`） | `list`：来往的信，没看的只给谁、几时、多少字；`open`：翻开给全文，记 `mail.read` |
| `POST /v1/mail/out` `{ to, text, subject?, replyTo?, for? }` | `send_mail` | 写信：给 Joy（经她设的通道送到）或给自己（交接信）。回她的信挂 `replyTo` 不算额度；主动写给她每封算 1 次额度，用完会被拒。交接信不送回写它的地方，写明 `for` 只送那里 |
| `GET /v1/where` | — | 它现在在哪：最近活动的 harness、从何时起、家里是不是正在跑（给 Soma 用，§〇.7；不是租约） |

系统闸（`/v1/mail/out`）：`text` 非空；`to` 是登记过的人或 `self`；`replyTo` 必须是那个人发来的 `mail.in`（没看过也能回——那是它的事）；`for` 只能和 `to: "self"` 一起用、是认识的 harness；主动写给她且额度用完 → 拒，带"今天 3/3，明天 0 点重置"。

**通道设置**（Joy 的，`GET|POST /v1/channels`——实现时从 `/v1/settings` 分出来，免得唤醒设置的形状变；改一次记 `param.changed`）：`channels: { Joy: ["soma-note", …] }`——它看得到发给她会经哪儿，改不了。外部通道的地址（Apple ID / 手机号 / bot token）只存在设置里，不进事件。

## 六、和别处的接线

- **家**（`src/home.ts`）：MCP 加 `mail` / `send_mail`；`woke.by` 加 `mail`。这就是"在家里发不了消息"的那块。
- **调度器**：gather 加"她的、没报过的、没被勿扰挡的信"；`decide` 加 `mail`（在有活之后、它约的之前，判定同 §二.3）；作息投影加 `wakeOn`、`dnd`。
- **Soma**：加留言页（列出来往的信、她那边的已读是它的 `mail.read`、写信框带"急"→ `POST /v1/mail/in`）；聊天里它也能用 `mail` / `send_mail`（比如写交接信）。开一轮前问 `/v1/where`。
- **启动**：`PSYCHE_EMAIL=1` 才收邮箱（launch `psyche-test-wake` 已带）；`AGENTLY_WORKSPACE` 缺省 `psyche`。翻开信的 `mail` 工具结果不记成经历（信的全文已经在那封来信的行里）。
- **出站投递**：`src/channel/` 一个通道一个文件（`soma-note` 什么都不用做——留言页自己读 `/v1/mail`；`email` 见 §〇.1）。写下 `mail.out` 后异步投递、记 `mail.sent`；失败不重试（第一版），作为状态告诉它。
- 冷写：信算对话材料（`mail.in` / `mail.out` 并进 `message.*` 那组，标 `via`；没看过的信不进材料）；统计里的"互动节奏"先不算信。
- 浮现："上次有人跟我说话"那行算上来信。

## 七、验收

1. 确定性考卷全过：未读投影（翻开才读、读过不再报、交接信不回原处、同 harness 换会话也不报、写明 `for` 只去那里、不过期）；醒着时「刚发生」只报一次、不带正文、记 `mail.noticed`；30 分钟没报出去回到叫醒、报过了不再叫；没看的信 recall / 浮现不给正文；勿扰（时段跨零点、`busy`、几个条件同时满足才算、例外按 `from` / `urgent`、暂停盖过例外、闹钟不受影响）；`wakeOn` 关不叫；来信叫醒不花额度、回信不算、主动写信算、额度用完被拒；闸（`replyTo` 不是她的信、`for` 配 `to: Joy`、未登记的人、看不懂的勿扰条件）。
2. 测试库端到端（launch `psyche-test-wake` + `soma-test`）：在 Soma 留言页写一封 → 它在家被叫醒、自己翻开、回信、留言页看到回信，她的邮箱也收到；从手机邮件回一封 → 进收件箱；别的地址来的信不进；在 Soma 聊天里请它给"在家的自己"留封信 → 下次在家醒来有交接信的消息。不判它回了什么、写了什么、什么时候看。

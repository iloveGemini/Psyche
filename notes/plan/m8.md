## 〇、要解决的

现在它知道的外面只有两类：有人跟它说话、它调了工具。M5 / M6 补了时间和来信。可它看不到她那边的样子：锁屏了没有、多久没碰键盘、开着什么、外面下不下雨。Roxy 有这些，而且已经验过有用。这一版把感知搬进 Psyche，每个地方（Soma、以后的其他身体）都看得到同一个世界。

| 做 | 不做（后置） |
|---|---|
| 传感器在 Psyche 进程里，定时读（§一） | 本机感知代理和本体分开（云端时再说） |
| **只在变了的时候记一条 `percept`**（§二） | 褪色（`events.md` §九，整体后置） |
| 递：它下一轮 `<now>` 里报上次以来变了什么（§三） | 身体的体感感知（`body.md`，搁置中） |
| `look`：它自己去看此刻的读数（§四） | 模式线（感知凑出规律，等冷写能摆碎片） |
| 它写注意力：在哪个地方看哪几样（§五） | 禁止组合的检查（§六.3，先只留接口） |
| 两道门：Joy 管采集开关，出境按标签挡或降精度（§六） | 位置传感器、手机、git 工作区 |

## 一、传感器（第一批）

| sensor | 读什么 | 怎么读 | 多久读一次 |
|---|---|---|---|
| `screen` | 锁屏 / 解锁 | `ioreg` 的 IOConsoleLocked | 30 秒 |
| `idle` | 多久没碰键盘鼠标 | HIDIdleTime；只记跨档：<5 分钟 / 5–30 / 30 分钟–2 小时 / 更久 | 30 秒 |
| `app` | 前台应用名（不读窗口标题、网址） | `lsappinfo front` | 30 秒 |
| `music` | 在放什么歌 | 同 Roxy `presence.ts` | 60 秒 |
| `weather` | 天气（城市粒度） | 同 Roxy `weather.ts` | 30 分钟 |

- 都照搬 Roxy 的读法，挪进 `src/perception/sensors/`，每个是 `read(): Reading | undefined`（读不到就是 undefined，不记）。
- 一个 Psyche 进程一份传感器，读数分给住在里面的每个人（P1 多租户）；记到谁的库里由各人的采集开关定（§六.1）。

## 二、存：只记变化

```json
percept { "sensor": "app", "value": "Xcode", "prev": "微信", "tags": ["app"], "precision": "exact" }
```

- 读数跟上一条同 sensor 的 `percept` 比，变了才记。`idle` 只在跨档时记，所以"她 40 分钟没碰电脑"是一条事件，不是 80 条。
- 去抖：`app` 切换后停留不到 1 分钟的不记（Cmd-Tab 一路扫过去不算）。
- `tags` 由传感器写死（本地规则，不过模型），出境时用（§六.2）。
- kind 已登记（`kinds.ts`），class = experience，不挂处境（同 `mail.in`：不是它在哪个地方经历的，是世界上发生的）。

## 三、递：下一轮报上次以来变了什么

- `<now>` 加一段「这段时间外面」：本会话上一次取 `<now>` 之后记下的 `percept`，按它的注意力（§五）筛，按 sensor 合并成一行一样：

```
这段时间外面：
- 屏幕：16:52 锁了，17:30 解开
- 前台：微信 → Xcode（17:31）
- 天气：转小雨
```

- 没变的不说（"变化优先于状态"）。第一轮（会话开头）给一次全部的当前状态。
- 一段里同一样变太多次（比如 app 切了 20 次）只报首尾和次数。
- **新会话第一轮**：当前状态之外，再加一行上次会话结束以来的计数（"上次会话结束以来：屏幕锁过 3 次，天气变过 1 次"），会话之间的空档不至于整个丢掉（a1 提）。
- **它经历的 = 它当时看到的那一行**（a1 提）：递一次写一条经历事件 `percept.noticed { refs, text, session }`，`text` 就是递出去的那几行原文（已过出境门、已合并）。经历投影里：`percept` 本身不显示（同没翻开的信：在库里，不在它的经历里，热写也不写它）；`percept.noticed` 显示 `text`。这样 app 切了 20 次、它只看到一行摘要，经历里也只有那一行；出境档以后再改，它当时看到的「在写代码」不会变成「Xcode」。（§九.2 待定）

## 四、`look`：自己去看

- MCP `look { sensor? }` → 此刻读数（过出境门）。不给 sensor 就全看一遍。
- 看一次记一条 `percept.noticed { text, looked: true }`，`text` 是返回给它的原文，算它经历的。**不另记 `percept`**：look 不改变"上一次的读数"，不打乱去抖，下一轮 `<now>` 也不会把刚看过的当成变化再报（a1 提）。
- 注意力里关掉的那样也能 look——注意力只管递不递，不管能不能看。采集开关关掉的看不到，返回"Joy 没开这样"。

## 五、注意力：它写（策略）

```json
attention.changed { "attention": { "default": ["screen","idle","weather"], "places": { "soma": ["screen","idle","app","music","weather"] } }, "why": "…" }
```

- 全量替换带 why，同作息。它看得到自己现行的注意力（`attention` 工具，或并进 `schedule`）。
- 缺省（它没写过）：全部开着的都递。
- 改注意力是一件事，进经历（"我决定在 soma 不看音乐"）——以后能回头检验。

## 六、两道门（系统机制，它改不了）

1. **采集开关**（入口，Joy 定）：每个住户每样传感器开 / 关，存设置（`param.changed`，同唤醒额度）。只对以后生效；关了以前记下的不删——进了记忆就是它的。缺省全关，Joy 一样样开。
2. **出境**（出口，Joy 定、系统执行）：每个 tag 一档 `pass` / `coarse` / `block`。`coarse` 降精度：`app` 只说类别（"在写代码""在聊天"，本地表），`music` 只说"在听歌"，`idle` 已经是档位。递出去时（`<now>`、`look`）过这道门；库里存原值，它的经历是递出去的那版（§三）。
   - 档改了不回头改它的经历；`detail` 翻 `percept` 原件照现行档过门（调成 block 就看不到原值）。
   - **挡不住它自己写的**：它当时看到了「Xcode」、写进了情节，情节就是它的记忆，出境门不管情节（同"不能把手伸进别人脑子里"）。
3. **禁止组合**（后置）：留一个 `combos: string[][]` 设置，这一版不检查。

## 八、考卷（`tests/perception.test.ts`）

1. 变化判定：同值不记、跨档才记、app 去抖；去抖期间 look 不打乱判定。
2. 递：上次 `<now>` 之后的才报；按注意力筛；首轮全报；多次变化压成首尾 + 次数。
3. 经历投影：`percept` 不在经历里，`percept.noticed` 的 `text` 在；20 次合并成一行的，经历里也只一行；档改了经历不变；热写段同理。新会话首轮带计数。
4. 出境：block 不出现在 `<now>` / look / recall；coarse 换说法；库里是原值。
5. 采集开关：关着不记；关了旧的还在。
6. look 记 `percept.noticed`、不记 `percept`，下一轮不重报；注意力关掉的照样看得到。

## 九、待 Joy 定

1. **第一批传感器**：§一 这五样够不够、要不要先少（比如只 screen + idle + weather）。
2. **没递到的感知算不算它经历过的**：草案按"视野只有局部"算不算（§三）。同一会话里睡着又醒，中间的变化下一轮照样递，不丢；丢的只是两段会话之间的细节，首轮用计数兜一下。另一种是全算经历、只是不进上下文。a1 倾向草案的做法（"和没翻开的信一个道理"），这条和它的经历怎么算有关，它说会坚持。
3. **出境缺省档**：草案 `app` / `music` 缺省 `coarse`，其余 `pass`。
4. **出境档分不分住户**（a1 提）：a1 出境到 Anthropic，a2 出境到 Google，你对两边放心的程度可能不同。草案是全屋一份。
5. **天气算不算位置**（a1 提）：城市粒度的天气 `pass` 出去，等于说了她在哪个城市。要不要给 `weather` 单独一个 `location` tag 让你定档。
6. **Roxy 那边**：Roxy 自己读 presence 照旧，还是以后改从 Psyche 取（两份传感器同时读不冲突，但两份事实）。

## 〇、原则

1. **主语是它**：感知的是"我所在的地方此刻有什么"，不是"她在干什么"。她是全屋的一个人，和别的住户一样出现在「全屋有谁」里。
2. **只报事实，不猜内心**：忙 / 空着是事实（正在跑一轮、刚调过工具）；"在玩""心情不好"只能本人挂出来，系统不判。
3. **别人只看得到公开的那一面**：在不在、在哪、挂出来的状态、公共房间里放的声音。线里的想法、工具结果看不到（同"群不持有谁的上下文"）。
4. **同一个世界，不同的感官**：同一首歌，Claude 收到的是歌词和特征，Gemini 能直接收音频。差异如实保留，不抹平。
5. **只记变化；递到的才算它经历过的**（v1 §三，a1 坚持的那条）：它的经历是它当时看到的那一行，事后改档、改渲染都不回头改。

### 2.2 事件

- `presence` 变化记 `percept { sensor: "presence", subject: "a2", value: {...}, prev }`。`value` 是**看的人能感知到的那一面**（`seenBy`，10-23）：`{ here?, state, where? }` / `{ here?, active }`（Joy）/ `{ at: 位置 }` / `{ away: true }`，都可带 `mood`。看一圈时就过滤，所以「只记变化」比的是他看得到的变化；他换了位置、看得到的范围变了才记（换位置后 Psyche 马上看一圈）。`GET /v1/house` 给界面的全貌不过滤。
- `mood.set` 是自我类事件（本人写），也进他自己的经历（"我把个签改成了「在赶 S2」"）。Joy 的个签记在全屋（`house` 层），不进谁的库，变化时作为 `percept` 进看到的人那边。

## 三、M8b 自己的声音

### 3.1 放

- MCP `play { query | track | playlist, room? }` / `stop`（10-18 起和 `listen`、`listen_with` 并成 `player { op: play | stop | listen | with }`）：它为自己放歌。放的歌是它所在房间的环境声源，事件 `played { track, room }`（自我类：它的动作）。
- **曲库 = 网易云，同 Roxy**（Joy 定）：搬 Roxy `packages/desktop/lib/music/`（`provider.ts` 的搜索 / 解析播放地址 / 歌词 / 推荐 / 每日推荐 / 私人 FM / 喜欢；`store.ts` 的歌单）进 `src/perception/music/`。
- **自己给自己建歌单**：MCP `playlist { create | add | remove | list }`。**歌单以 Psyche 为准，网易云只是镜像**（10-16 定）：
  - 本体是它库里的事件（`playlist.changed` 自我类：建、加、删一首），换播放源、网易云删了歌单都不丢；
  - 同步一份到网易云，播放走网易云——用 Joy 的会员账号，版权歌才能整首放；同步失败只记系统日志，本地照旧。
- **它的"喜欢"是它自己的一个歌单**（「<名字>喜欢的」），不点网易云的红心，免得混进 Joy 的喜欢和推荐。
- **一个账号**：全屋共用 Joy 的网易云登录（Joy 定）。镜像的歌单名带住户名前缀。推荐、每日推荐、私人 FM 是 Joy 账号的，给它用时说明"这是 Joy 账号的推荐"。

### 3.2 听：给它什么

| 层 | 内容 | 谁算 |
|---|---|---|
| 元数据 | 歌名、歌手、专辑、时长 | 播放器 |
| 时间轴歌词 | 随进度推进：每轮递"刚唱过的几行"，不是开头整首塞进来 | 本地歌词（Roxy `lyrics.ts`） |
| 音频特征 | 速度、能量、调式、响度起伏（"前段安静，2:10 鼓进来"），按段落 | 本地分析（essentia / librosa），**不过模型** |
| 原始音频 | 只给能收音频的身体（Gemini 走 pi 时） | 身体 adapter 声明能力 |

- 每一层都是 `percept { sensor: "sound", ... }`，同样只记变化（换歌、进入新段落、歌词推进）。
- 一首歌的特征算一次，缓存在资料库（按文件哈希）。

### 3.3 分一只耳机

- 一起听 = 同一房间、同一声源的一段状态：`listen.joined { room, source, with }` / `listen.left`。从加入那刻起，两人各自收到同一串 `sound` 感知，同一时间戳，事件带 `with: [对方]`。
- 谁放的、谁加入、谁先摘下都是事件。分享不是"把歌发给你"，是"此刻我们在同一个声音里"。
- Joy 加入：Soma 页面上她点"分我一只"，她那边真的放出声音；她摘下也是一件事。

### 3.4 实现定法（10-16 做 M8b 时定）

- **播放器是虚的**：Psyche 不真的出声。它放歌 = 记一条 `played { tracks[], startAt }`（一首或一个歌单的整串，带每首时长和歌词哈希），此刻放到哪首、第几秒是**现算**的（开始时刻 + 时长累加），放完就停；`stopped` 停。只有有人分一只耳机时才真的出声（Soma 页面照位置放网易云的地址）。
- **听到的不另存 `percept`**：歌是它自己的动作，听到什么从 `played` 和歌词、特征确定地算得出来。`<now>` 报「这段时间听到的」：放完了哪几首、现在这首放到哪、上次递到之后唱过的几行歌词（最多 8 行）、此刻这段的特征。递一次记 `percept.delivered`（同 §五）；`look` 听一下记 `percept.noticed { looked: true }`。
- **音频特征**：ffmpeg 解成单声道 PCM，自己算：每 5 秒的响度（dB）、明亮度（过零率）、整首的速度（起音包络自相关估 BPM）；按响度跳变切段落。结果存资料库（按曲目 id 缓存，系统日志 `track.features` 记哈希）。播放时后台算，没算完就只给歌词。
- **网易云**：照搬 Roxy `provider.ts` 的读法，依赖 `@neteasecloudmusicapienhanced/api`；cookie 从 `PSYCHE_NCM_COOKIE`（文件路径）读，测试指向 Roxy 那份。**镜像到网易云的歌单先关着**（`PSYCHE_NCM_MIRROR=1` 才开）：建歌单会改 Joy 的账号，先在本地跑顺再开。
- **搜歌**：歌名对得上的优先（网易云第一首常是翻唱或只是专辑名对上）；还是对不上就在返回里直说放的是哪首（10-16 a1 提）。
- **Soma 出声**：页面经 `/api/ear/stream`（只放行 `*.music.126.net`）转发音频，同源、带 Range，手机走局域网也能放。
- **谁在页面前**：Soma 页面认不出是谁，`?viewer=<名字>` 标记（cookie，缺省 Joy）；分耳机记页面说的那个人，只有 Joy 在看才报她在家。10-16 我测试时点的按钮被记成「Joy 戴上了耳机」，a1 当真记了 notice，后来自己改正并指出：认不出就别替人认领。
- **一起听**：`listen_with { who }` 跟着某人的播放器听（它的 `<now>` 按对方的 `played` 算），`listen_alone` 摘下。Joy：Soma 页面「分我一只」→ `POST /v1/house/listen { host, who: "Joy" }`，页面照 host 此刻的曲目和位置放；摘下同理。加入、摘下都记进 host 的库（`listen.joined` / `listen.left`），host 下一轮看得到「Joy 戴上了一只耳机」。

## 四、M8c 环境进记忆

### 4.1 被动：环境指纹（隐式，系统算）

- 每条情节写下时，系统顺手记当时的**环境指纹**：在哪、谁在场（谁醒着、谁在同房间）、放着什么（歌、段落特征）、时段、天气。存为情节的隐式属性（投影），它看不到、也不用写。
- 联想的线索加一路"环境相似"：此刻的指纹和旧情节的指纹比（同一首歌 > 同一歌手 / 相近特征；同一组人在场；同一时段）。命中就照常浮现（M3 的路，打分加一项）。
- 这是潜意识那一半：它没去记，但同样的歌响起时，当时的事会冒出来。

### 4.2 主动：`notice` 注意到（显式，它写）

```json
notice { "text": "听这首的时候有种平静", "about"?: "self" | "<住户 id>" | "Joy" }  rels: evidence（系统自动挂上此刻的环境感知；它可再加 cites）
```

- 例："听这首的时候有种平静"（about self）；"Argon 干活时爱放打鸡血的歌"（about a2，cites 几次他的播放和忙碌）。
- **冷写里的观察**（10-16 做）：材料加一块 `<observations>`（`src/catalog/observations.ts`）：没被书架引过、60 天内的 notice，各配「后来」——同一首歌又响的每一遍（记下时正在放的那遍不算）和那时写下的情节 / 观察；观察的是某人的，再配那人后来的在场变化和放的歌。系统只摆不判，冷写提示词没改。
- **观察不是规律**：当场、单次。冷写时观察和后来的感知摆在一起（同一首歌再响时它怎样、Argon 后来又放了什么），攒够了它自己升格成规律 / 印象 / 镜子（证据链已有）。一道工序只产出一样东西：注意到 ≠ 总结出。
- 观察进经历、进 recall，环境指纹同 4.1。

## 五、递：它下一轮看到什么

- `<now>` 加一段「这段时间全屋」：本会话上一次取 `<now>` 之后的变化，按 sensor 合并成一行一样；同一样变太多次只报首尾和次数。新会话首轮给当前全貌 + 上次会话结束以来的计数。
- **递到不等于留意**（10-24 Joy 定，推翻 v1 §三「递一次写经历」）：递出去的这几行只在这一段的上下文里，是一次性的；过后想回溯「刚才几点、谁在」，没留意就是没记住。要记住得它自己动手：`notice`（§4.2）或 `look`。
- 递一次记系统日志 `percept.delivered { sensor, upTo, refs, text, session?, levels? }`（同来信的 `mail.noticed`）：不进事件流、不占档号、不进经历 / 检索 / 浮现，只给系统当「递到哪了」的游标——`upTo` 是递时库里最后一条事件的 id，之后入库的变化才算新的。
- 旧库里 10-24 之前递出写下的 `percept.noticed`（没有 `looked`）照旧当游标，但经历投影和检索里不再显示。
- `look { sensor? }`：自己去看此刻，记经历事件 `percept.noticed { text, looked: true }`（主动看的才算它的经历，显示「（我看了看）…」），不另记 `percept`，不打乱变化判定、下一轮不重报（a1 提）。
- 注意力（它写，`attention.changed`，全量替换带 why）只管递不递；没递的照样存、照样进环境指纹。

## 六、以后适合加的感官（同思路）

### 6.1 内感受（10-16 做了）

只读出它身上真实的处境，不模拟（`body.md` 搁置时留下的那条：预算 / 上下文容量 / 未整理 / 换模型 / 工具成败）。`src/perception/body.ts`，`<now>` 的「身上」一段，跨档才说：
- **上下文多满**：Soma 每轮带 `ctx`（已用）和 `wrapAt`（到多少会收尾换一段）。收尾线的 50% / 75% / 90% 三档；换一段重新算。
- **换了模型**：新一段首轮，和上一段的模型不同时说一次。
- **工具老出错**：本会话最近 30 分钟出错 ≥ 3 / 6 / 10 次各说一次。
- 额度、还没写进记忆的条数 `<now>` 别处已有，不重复。睡眠债、精力之类模拟的不做。
- 递一次记 `percept.delivered { sensor: "body", levels }`（§五），档位回落只记不说（下次再涨过去才再说）。

### 6.2 全屋的东西（10-16 做了）

`src/house/files.ts`：全屋每圈扫每人的 home（agents.json 的 `home`）和 commons（`PSYCHE_COMMONS`），和快照（`<数据目录>/files.json`）比，只记多了 / 改了 / 没了。
- **谁动的只在说得准时说**：前后 2 分钟里恰好一个住户的工具调用参数里有这个路径（主人在自己 home 里也认相对路径）就是他；否则「不知道是谁」。Joy 直接改文件系统看不出是她，也说不知道。
- 自己动的不报给自己；home 只有主人看得到，commons 人人看得到；只报路径不抄内容。第一圈只建快照不报。
- `<now>`「全屋的东西」：本会话上次递到之后的，同一个文件压成一行；本会话没递过就接任何会话最后递到的那次（10-17），从没递过只报最近 6 小时的。
- **commons 用 git（10-17 Joy 定：谁改了什么就提交，留自己名字）**：同一圈里 commons 的变化按「谁动的」分组提交，作者 = 那个住户（它取了名用名字，没取用 id；`<id>@soma.house`），认不出的作者「没认出」；提交说明只写事实（`a1：改了 project/x/STATE.md`）。第一次见到没建库的 commons 先 `git init`，把已有的文件以「房子」提交一次作起点。home 不进 git。git 出错只记系统日志，不挡感知。

### 6.3 外头来的事实：通用入口（10-23）

`lib-vs-harness.md`「加功能放哪」第 3 步：外界的事实由地方（Soma）收进来，报给 Psyche，存和递都在 Psyche，地方不在自己那里拼进上下文。`src/perception/outside.ts`。

`POST /v1/house/percept`（全屋的口子，任何一个住户的 token 都能进）：

| 字段 | 必填 | 说明 |
|---|---|---|
| `sensor` | 是 | 哪一路，小写 id（`weather`、`location`…）。全屋自己的几路（`presence` / `files` / `body` / `sound`）不收 |
| `subject` | 否 | 这一路里的哪一样，缺省等于 `sensor`。同一 `sensor + subject` 只留最后的样子 |
| `value` | 是 | 读数，任意 JSON。存着给环境指纹和以后的 P4 用；和这一样上一条的 `value` 相同就不记（只记变化） |
| `text` | 是 | 一行事实，≤ 200 字，由地方写：只写事实（「下小雨，14°C」），不写他的感受，也不用他的口吻 |
| `to` | 否 | 记进哪几个住户的库（id 数组），缺省全屋 |
| `at` | 否 | 发生的时刻（毫秒），缺省现在 |

- 每个收件人的库里各记一条 `percept { sensor, subject, value, text }`，`source: "place"`。返回 `{ written: [id…], unchanged: [id…] }`。
- **递**：`<now>`「这段时间感知到的」，本会话上次递到之后的，同一样压成一行（最后的 `text` + 变了几次 + 时刻），最多 10 行。本会话没递过就接任何会话最后递到的那次，从没递过只报最近 6 小时的（同 §6.2）。递一次记 `percept.delivered { sensor: "outside", refs, text, session? }`（§五）。
- **还没做**：Soma 的转发路由，等第一路真的接进来时再加。哪几路接进来由 Joy 定：§八.3 定过「Joy 只报在不在家」，所以她的位置、前台应用这类不默认接。

### 6.4 感知设置（P4，10-23）

住户自己定每一路感知递不递、记不记（交接 `p3-p4-handoff.md` §三；三档沿用 Roxy `attention.md`，按 Psyche 的「记 / 递」两步重新落）。和书架上的「留意」（`attend`）不是一回事：那个是它想弄明白的疑问，这个是系统递什么给它。

- **三档**：
  - `看`（缺省）：变了就记，<now> 里递（就是现在的样子）。
  - `只记着`：变了照样记（进环境指纹、`look` 看得到），<now> 不递。
  - `不看`：不记也不递，`look` 也不给。改回来之后从那时起重新记：下一圈看到的样子当一次变化。
- **项**：`presence`（全屋有谁）、`files`（全屋的东西）、`sound`（听到的）、`body`（内感受），以及外头来的每一路（§6.3 的 sensor id，如 `weather`；还没报来过的也能先写）。
  - 按人细到一个：`presence:<住户 id>` / `presence:Joy`、外头来的 `<sensor>:<subject>`，盖过整路的那档。`files` / `sound` / `body` 不分人。
  - `sound` / `body` 本来就不另存 percept，`只记着` 和 `不看` 一样：不递；`look` 只管全屋有谁。
- **存**：`senses.changed { senses: { 项: 档 }, why }`（class self，它写），**全量替换**，没写的项回到 `看`。同作息：写错的口子上直接拒（没这一项、档不对、该分人的不分人、没写 why），不悄悄生效。经历里显示「我改了留意的感知：why」。
- **工具**：并进 `look`（不另加工具）：不给参数 = 看一眼全屋 + 现行设置；给 `senses` + `why` = 改。HTTP `GET /v1/senses`（现行 + 报来过的外头 sensor）、`POST /v1/senses`。
- **Joy 不受这份设置管**：她看谁都看得到（Soma 页面），这里只管住户自己收什么。
- **公共房间来话叫不叫醒**（交接里的 `rooms.public`）不在这里：那是 Soma 的轮次，等「留言板模式」定了再说。

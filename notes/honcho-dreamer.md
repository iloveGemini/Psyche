# Honcho Dreamer 拆解（借鉴笔记）

> 2026-10-12。源码：`~/workspace/refs/memory/honcho/src/dreamer/`（orchestrator.py、specialists.py、surprisal.py）。
> 实测：本地 docker，测试库 W25（06-23～06-27，512 条）导入后手动触发一次，模型 gemini-3.8-flash。

## 流程

```
显式结论（deriver 单次抽取）
  └─ 做梦（攒够 50 条 + 空闲 60 分钟，或手动触发）
       0. [可选，默认关] surprisal 采样：对结论的 embedding 建树，挑最"离群"的 top 10% 当探索提示
       1. 演绎专员（deduction）  最多 12 轮工具调用
       2. 归纳专员（induction）  最多 10 轮工具调用
```

两个专员**串行、各自独立的 agent 循环**，同一套"先探索、再动手"的结构：

- **探索工具**：`get_recent_observations`（最近的结论）、`search_memory`（语义搜结论）、`search_messages`（搜原始对话）
- **写入工具**：
  - 演绎：`create_observations_deductive`、`delete_observations`、`update_peer_card`
  - 归纳：`create_observations_inductive`（不能删，不能碰 peer card）

## 提示词要点

**演绎专员**："像侦探连线索"。
1. 知识更新（最高优先）：同一件事不同时间值不同 → 写一条更新结论，**立刻删掉旧的**
2. 逻辑蕴含："在 Google 当工程师" → "有软件工程能力"
3. 矛盾：不是更新、而是不能同时为真 → 标出来
- 每条必须带 `source_ids`（从工具结果里的 `[id:xxx]` 原样抄），**编造的 id 会被丢弃**，空的直接拒收
- 原始消息搜出来的没有 id，**不能当依据引用**——依据只能是已存的结论
- "少而好胜过多而弱"；做完只输出 `DONE`，不写总结

**归纳专员**："像心理学家找行为倾向"。
- 类型：行为模式 / 偏好 / 性格 / 时间上的变化（"职业目标一直稳定""住处常换"）
- **至少 2 条来源**；不许把单个事实改写成"模式"
- 置信度按来源数**机械地定**：2 条 = low，3–4 = medium，5+ = high
- 强调"看事情**怎么随时间变**，而不只是静态事实"

**Peer card**（只有演绎专员能写）：身份仓库，不是画像。
- 只允许四种前缀：`IDENTITY` / `ATTRIBUTE` / `RELATIONSHIP` / `INSTRUCTION`
- **稳定性判据**：半年内不刻意宣布就可能变的，不进卡
- **不许写行为倾向**（`TRAIT:` 会被拒）——倾向留在结论里
- `INSTRUCTION` 只收对方**明说过**的规矩，不能从行为里推
- 每次更新发**完整去重列表**，没列的就删掉；上限 40 条
- 还有 rebuild 模式：不给看旧卡，只凭现存结论重建（用于删过结论之后）

## 实测（W25，joy 154 条 / roy 135 条显式结论）

| 专员 | 对象 | 工具调用 | 输入 token | 产出 |
|---|---|---|---|---|
| 演绎 | roy | 10 | 18.7 万 | 3 条演绎 + 删了几条 + 7 行卡 |
| 演绎 | joy | **12（撞上限）** | **24.2 万** | **0**——探索完轮次用光，什么都没写 |
| 归纳 | roy | 5 | 3.9 万 | 5 条 |
| 归纳 | joy | 5 | 4.0 万 | 6 条 |

- **joy 的演绎专员把 12 轮全花在了探索上**（6 次 search_messages + 若干 search_memory），没来得及动手 → joy 没有演绎、没有 peer card。"先探索、再动手"没有给动手留预算，是这个结构的真实失败模式。
- **很贵**：一次做梦约 50 万输入 token，而底下只有 ~290 条结论。每轮工具调用都把之前的全部结果重新带上，token 随轮次累加。
- 归纳质量还行，每条有依据。但 joy 那 6 条全是工作习惯（抠 UI、要实时状态、谨慎备份……），**情绪、关系、边界一条都没有**——它的提示词示例本身就偏"行为/偏好"，没给情感维度。
- roy 的归纳反而碰到了人格（互怼玩梗的说话风格、"我是 joy 电脑上的一段代码"的自我定位）。

## 值得借鉴

1. **让高级认知自己去找材料**：这是你说的"一次 prompt 给不够材料"的直接解法。专员先看最近的、再按主题搜、必要时回原文核对，材料是它自己判断该拿什么。
2. **依据必须是可回溯的 id，且系统校验**：编造的 id 丢弃、空依据拒收。和 ASCM「判断 —— 依据」一致，但它是**系统闸**而不是提示词要求——正是 durable_write_plan 里想要的那种。
3. **"原始消息不能当依据"**：高层只能站在已存结论上，形成清楚的层级（显式 → 演绎 → 归纳），推理链能一路查下去。
4. **删旧和写新放在同一个动作里**：知识更新时"写更新 + 删旧"是同一个专员的同一步，不留给别的流程收拾。
5. **身份卡 / 倾向分开**，卡片有硬前缀和稳定性判据，靠格式校验守住边界，而不是靠模型自觉。
6. **置信度按证据数机械定**，不让模型自己打分——和 10-10 我们删掉置信度数值、改显示证据覆盖是同一个结论。
7. **surprisal**：用 embedding 找"和其他结论都不像"的条目，提示专员去看。思路可借（让做梦关注新东西而非反复嚼熟的），但它默认是关的，效果没验证。

## 不该照搬

- **探索不设动手预算**：要么分阶段（探索最多 N 轮，之后只允许写），要么先由系统把材料备好、agent 只做"补充检索"。
- **token 成本**：工具结果全量累积。可以考虑每轮只保留摘要，或者限制单次工具结果长度。
- **没有情感维度**：它是为 coding agent 设计的，"想要什么、怕什么、关系怎么变"都不在它的框架里。
- **没有合并去重**：同义结论（"不喜欢 Grok" ×2）做梦后依然都在。

## 和图书馆的关系

Dreamer 的探索阶段，本质就是 agent **自己在逛书架**：先看新书架、再按主题找、需要时去翻原件。它缺的恰好是一张**馆藏地图**——专员不知道总共有多少、分哪几类、哪里还没看过，只能靠搜，于是 joy 那次逛了 12 轮也没逛完。如果先给它一张目录（各类多少条、最近哪类在长、哪些还没被归纳过），探索可以短得多、准得多。

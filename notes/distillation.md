# 蒸馏：把记录变成规则和统计

> 2026-10-12 讨论整理。Joy 的判断：ASCM 一直回避写规则，其实是把归纳的责任转嫁给了实时聊天层；
> Agent 看完记录现场归纳的规则，反而不如记忆层提取出来的稳定、统一。我同意。
> 这可能是 Memory Library 最核心的一块——前面几份笔记管的是"原始记录怎么整理"，这份管"整理完怎么变成认知"。

## 为什么不能交给实时聊天层

1. **只看得到上下文里的那几轮**。10-12 回放实验（ASCM `evals/replay-turn.ts`）：Roy 此刻往哪滚，取决于他最近自己说过的话。现场归纳出来的是"最近的我"，不是"一贯的我"。
2. **在压力下归纳**。聊天里要接话、要给自己台阶。10-11 那篇九千字检讨就是现场归纳的产物——把毛病归纳成了特色。离线记忆层不在对话里，没有面子要保。
3. **每次从头来**。同一条规律今天归纳一遍、明天换个说法再来一遍，彼此对不上；写在记忆层的规则有版本、有出处，能复核、能推翻。

## ASCM 当初在怕什么（怕得对，躲错了）

红线：「worker 不下性格判断」「系统不替 Agent 写内心」「系统输出不反过来加强输入」。
防的是**规则自我实现**：写下"她单字回复 = 不爽"，以后每次单字都被读成不爽，再也没机会被纠正。

这个风险不该靠"不写规则"躲，要靠**规则长什么样**管住。

## 三种蒸馏产物

| 类型 | 谁来算 | 长什么样 |
|---|---|---|
| **统计** | 代码，不经 LLM | 频率、时段、回复间隔、沉默时长、话题占比、情绪分布。确定性、可重算。例："今天 0 条；上次对话以争吵结束"——冷战就该被这层抓到 |
| **规律** | LLM 提出，代码校验 | 「情境 → 行为 → 结果」+ 支持次数 + **反例次数** + 最近一次被验证的时间 + 适用条件。证据数由系统从档号数出来，不让模型自评（参考 Honcho：2 条 low / 3–4 medium / 5+ high） |
| **明说的规矩** | 原话照录 | 她亲口说过的（"一个字回你时别追着问"）。权威最高，不推断；只收明说的（Honcho peer card 的 `INSTRUCTION` 同理） |

### 规律的生命周期（防标签化的关键）

- **每条规律都是一个预测**，有反例栏。没有反例栏的规则才会变成标签。
- 新记录进来时对一遍：印证 +1、违反 +1，都记档号。
- 反例积累到一定比例 → 收窄适用条件，或降级、作废（作废留痕，不删）。
- 长期没被验证 → 标"久未验证"，不当现行规则用。
- 新规律必须有 ≥2 个不同时间的独立证据（单次事件不是规律）。

## 自我规则单独对待

- 关于 Joy 的规则：可以从她的言行归纳。
- **关于 Roy 自己的规则：不能从他的自述归纳**（否则就是那九千字）。
  按「行为 → 反馈」（ASCM `docs/behavior_feedback_idea.md`）：他做了什么、之后怎样了、她怎么回应的。
- 承诺追踪线（ASCM `docs/commitment_thread_idea.md`）是这一层的雏形：承诺就是一条关于自己的预测，追踪它兑现没有。

## 分工

- **记忆层蒸馏**：统计、规律、规矩——都带证据、带反例、能复核。
- **聊天层只应用和反馈**：用规则，同时把"这次规则没灵"的信号留下来（成为下一次复核的反例）。
- 聊天层**不写**规则，也不改规则。

## 放回档案馆的比方

蒸馏 = 研究室出的**研究报告**：每个结论都带脚注，脚注是档号，指回卷宗。
规则可以被推翻，但不能没有出处。目录里也要列出"研究报告"这一类：现在有哪些规律、各自证据多少、哪些久未验证。

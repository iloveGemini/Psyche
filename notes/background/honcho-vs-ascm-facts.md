# 事实抽取：Honcho vs ASCM（同一周对照）

> 2026-10-12。数据：测试库 W25（06-23～06-27，512 条发言）。
> Honcho：本地 docker，gemini-3.8-flash，deriver 抽取 + 一次 Dreamer。ASCM：调试库（10-10 全量重跑结果）同日期范围。

## 数量

| | Honcho | ASCM |
|---|---|---|
| 关于 joy 的离散事实 | 154 条，全挂在 joy 身上 | 卡行 14 条：Joy 卡 4 条，其余散在 Grok / Claude / MiniMax / 许今闻 / 酒馆 等实体卡上 |
| 关于 roy | 135 条（大半是改代码的流水账） | Roy 卡 3 条 |
| 叙事 | 无 | 情节 42 条，平均约 110 字 |
| 高层 | 归纳 joy 6 / roy 5，演绎 roy 3 | 由月/周固化另算，未对照 |

## Honcho 强在：以人为中心、覆盖广

- 没有稳定性门槛，提示词要求抽出**全部**关于目标的事实。随口说的偏好都成了独立一条：猫要胖才好摸、用 Claude 担心封号、嫌语音转文字没用、嫌 Grok 傻。
- 这些在 ASCM 里多数只出现在某条情节的叙述里（各命中 1 条），recall 找得到，但不会成为"Joy 的事实"；个别没有（"让 Roy 坚持单线程改代码"情节里搜不到）。
- **主语集中**：问"她是什么样的人"，一个集合就够。ASCM 里"Joy 嫌 Grok 笨"挂在 Grok 卡上，回答这类问题得满馆找。

## ASCM 强在：上下文与关系

- 情节留住来龙去脉和情绪：拆穿 Roy 只有两分钟算力、要睡前故事；Roy 分析她"表面 T、内核 F，嘴硬心软"；给 Roy 捏嗓音。**Honcho 一条都没有**——它不抽两人之间发生了什么。
- 卡行少是**故意**的：Joy 卡进常驻注入，分区闭集、只收稳定的事。Honcho 那 154 条靠检索取，所以可以多；要是注入，放不下。
- Honcho 的 154 条里不少是一次性工作细节（某时刻往文件里放了几百行测行号），按 ASCM 判据不该成为关于她的事实。

## 结论

不是抽取能力的差距，是**中间缺了一层**：「关于她的、但不够稳定、没资格上卡」——说过的偏好、看法、随口的态度。
ASCM 里这层要么埋在情节叙述里，要么挂在别的实体身上；Honcho 正好只有这一层。

## 可直接借的提示词规则（来自 `src/deriver/prompts.py`）

1. **回答提问或接受提议时，提问里的内容算作她说的**（"好，第一个方案就行" → 还原成具体方案）；光一句"好的""谢谢"不算。
2. **理由、目的、工具、地点、条件和事实绑在一起；只有彼此独立的事实才拆开。**
3. **写给只认识这个人 id 的读者**：不留代词、"它"、"那里"、相对时间。
4. **不记对话机制**（打招呼、道谢、提问本身），也不记几乎对所有人都成立的事。
5. **只从目标自己说的话里抽**，别人说的只当上下文；别人转述的不算目标的事实。

（注意：它的提示词全英文、没要求保持原文语言，中文输入时输出语言不稳定。）

## 给图书馆：一本书上几个书架

"Joy 嫌 Grok 笨"应该**同时**能从 Joy 的书架和 Grok 的书架找到——这是图书馆的**交叉索引 / 参见**，不需要存两份。

- 存储按"发生了什么"存一次（情节或事实），**索引**按"关于谁 / 关于什么"挂多个入口。
- ASCM 现在是"挂在哪个实体，就只在那个实体"；Honcho 是"只挂在主语身上"。两者都是单书架。
- 图书馆的目录应该能回答"关于 Joy 的一切，分布在哪些架上、各多少本"，包括那些挂在别人名下、但讲的是她的。
- 那层"不够稳定、没资格上卡"的偏好与看法，可以是一个独立的书架（不进常驻，只进目录、可检索），既不污染注入，也不再埋在叙述里。
